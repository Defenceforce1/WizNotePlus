# 原生列表空标签缓存与内存归因

`list-lifetime.cpp`另验证生产列表移除项的所有权。它链接真实View／item和临时
元数据库，通过manager删除信号移除300次；每轮用正常DeferredDelete边界观察
QPointer，不强制GC或清缓存。旧组移除后302、列表析构后303个观测对象仍活着；
新组均0。最后只回收本夹具的旧组遗留对象，避免诊断本身继续泄漏。

旧19项与首次新19项为对照，不重复累计。最终新组编译时定义
`WIZ_LIST_LIFETIME_EXTRA`，26项含私有移除函数的无效索引／分组保护、选择信号
阻塞及菜单快照边界；不改变产品可见性或数据。三条移除路径的接线另检查源码，
不冒称正常主窗口中修改／参数筛出分支已端到端验证。对象和独立图像载荷释放
不是整个App内存降幅，也不解决相邻WebEngine高水位风险。生产和夹具均不联网。

`tag-cache.cpp`链接匹配版本的生产对象，替换普通客户端main，不调用普通
账号入口。设置项目内临时数据根和两个临时QSettings，创建只含合成元数据的
笔记与标签。临时App必须带对应SQL资源；没有正常主窗口、账号或笔记正文。

`--baseline`期望500次标签读取产生500次真实SELECT；`--optimized`期望1次。
必须分别链接旧／新版本对象，不能用同一当前优化程序冒充旧对照。SQLite
trace只计本测试连接的标签SELECT；不插桩产品、不新增公开接口。测试专用
private／protected可见性仅允许观察自有类缓存和这个临时连接，不改生产头。

验收覆盖null未加载与成功空串区分、现有clear失效、重载、隐藏根目录来回、
正标签显示不变、删除最后标签、失败不缓存及恢复重读。优化组另验证真实
manager文档修改信号触发item.reload，避免仅手动清缓存掩盖陈旧显示。不可用
表由临时事务内改名模拟并回滚，不访问真实库，不属于网络／安全测试。

首稿check辅助函数未返回bool，编译中止且未进入功能断言；修测试后旧21项、
初次新21项通过，再补修改通知关联后最终新22项通过。只将最终22项计作产品
关联验收，保留旧对照和编译失败，不能叠加重复数量。

相邻reader-opening诊断新增`retention-yield-editor-vm`，默认旧模式仍保持原
十秒边界；新模式只在隔离程序中观察同profile关闭八次、空闲10／30／60秒的
自有任务VM记账。读取系统SDK定义的task_vm_info字段，不读内存正文或其它
进程地址，不附加调试器，不强制GC、清缓存或增加生产自动释放池。

原生内部／可复用页的差异是归因线索，不代表确认某个组件泄漏或已修好常驻
内存。完整公式／PDF／组件矩阵不因这一列表改动重新运行；真实主窗口长期
使用仍不能由本合成入口替代。
