# 第二组十轮性能与内存对照

本组以第一组十轮完成后的源码为基线，逐项验证新的惰性准备、DOM遍历及通知
合并，不把上一组实现重新计为十轮。只读取自有扩展与测试，不解析捆绑编辑器。

`pure.cjs <1..6> <before目录> <新结果JSON>`在独立VM比较直接修改前和当前
自有转换函数的字节输出，记录原文getter、代码／数学保护数组及原式表调用。
大样本预热两次，再取七次中位时间。marked仅替换为恒等函数，此组不是完整
Markdown／MathJax验收；原生实际接口另测。所有结果路径必须为绝对路径，
已有结果拒绝覆盖。快照包含editorHelper.js、markdownEnvironments.js、
latexTheorems.js及欢迎页index.js。

`dom.cjs <7..10> <before目录> <新结果JSON>`通过已有Playwright和本机Chrome
在离线headless页面运行自有代码，保留Chrome沙箱。分别核对标题解析临时数组、
引用候选祖先查找、嵌套逻辑文本区剪枝、通知合并及页面退出后的停止。标题／
链接／上下文偏移／保护字节和源HTML恢复必须一致。DOM数组和API调用减少不
等同于进程RSS或整App速度下降。

欢迎页的合并只用于数据库通知：同一刷新函数至多一个通知触发的执行和一个
待处理尾刷。显式用户操作仍等待原有函数，正在保存的任务不会被取消。失败
记录后允许下一次通知重试；非缓存pagehide取消尚未启动的计时器。

第九项初次测试将1500组子树的旧查询次数阈值误写为大于10000，实际7531，
新实现6。输出与保护字节已一致；纠正测试阈值为大于7000后只重跑该项，旧
失败结果必须保留。不是通过删除功能断言让产品回归变绿。

执行时不要启动正常客户端、使用固定用户资料、访问网络或禁用保护。真实
编辑器合成验证、双PDF和逐轮返回顶层事件循环的原生内存对照单独留证；
不重复数据库／归档／全组件矩阵，不用强制GC、清缓存或销毁共享profile造收益。
