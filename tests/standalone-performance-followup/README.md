# 第二组十轮性能与内存对照

第259轮`theorem-candidates.cjs <before目录> <新结果JSON> prototype|product`
验证自有投影器的惰性原文提供者：先复用既有HTML文本过滤和完整标记匹配，
只有可处理的候选才读取当次权威原文；原有字符串参数接口不变。最终101项
真实DOM／marked差分，10类代码／忽略HTML／非法结构少读一次，16类定理／星号、
嵌套、引用、前置回调、错误／恢复及字符串接口输出逐字相同。无需访问私有引擎。
before目录上级preflight.json指定本项目隔离根，浏览器临时目录在其runtime下；
最终报告拒绝覆盖，不重复累计原型或以前阶段检查。

第258轮`theorem-gate.cjs <before目录> <新结果JSON> prototype|product`仅核对
自有beforeMarkdownRender的读取门槛，采用真实离线DOM／marked和合成公开getter。
6类无定理／未知环境／代码字面量、8类定理及星号形式共16类、错误回退、自定义
前置回调及恢复，最终103项差分检查。无受支持定理前缀时保留原HTML并不读原文；
支持的定理仍新读一次，输出逐字一致，无跨回调缓存。真实getter的1→0及耗时
由reader-opening的literal隔离场景单独确认，不把此DOM检查当作原生性能证明。
before目录上级preflight.json必须指定本项目隔离根；已有结果文件拒绝覆盖。

第248轮`theorem-source.cjs <before目录> <新结果JSON> prototype|product`以真实
离线DOM／marked和合成公开getter，先在内存原型验证，再要求产品源码逐字
匹配原型。16类投影、8次新原文、前置回调、解析／getter错误及恢复、直接
辅助接口回退共86项；三个正文重复getter 3→0，顶层回调含必要读取4→1。
真实getter与双PDF另测，不把DOM替身当原生内存证明。新输出拒绝覆盖，项目
阶段before上级须有preflight.json指定新建隔离根，浏览器HOME／临时profile
在该根内，沙箱保持、所有外部请求拒绝。初次向marked只读导出赋值未成功
注入异常的夹具失败单列保留；最终替换合成页全局parser，恢复原值于finally。

第247轮增量`source-snapshot.cjs <before目录> <新结果JSON>`仅比较自有同步
转换回调。快照目录需markdownEnvironments.js和latexTheorems.js；不读取受限
编辑器，以公开getter模拟器验证26类逐字输出、8次原文变化、异常／恢复、
自定义原回调改变原文、另一次回调必须新读、惰性和独立引用接口不变，共79项。
裸公式加普通ref的同次getter 2→1。只复用该次调用局部变量，不跨回调或笔记；
真实公开接口及必要双PDF关联另在reader-opening检查，不以此VM结果替代。

本组以第一组十轮完成后的源码为基线，逐项验证新的惰性准备、DOM遍历及通知
合并，不把上一组实现重新计为十轮。只读取自有扩展与测试，不解析捆绑编辑器。

`pure.cjs <1..6> <before目录> <新结果JSON>`在独立VM比较直接修改前和当前
自有转换函数的字节输出，记录原文getter、代码／数学保护数组及原式表调用。
大样本预热两次，再取七次中位时间。marked仅替换为恒等函数，此组不是完整
Markdown／MathJax验收；原生实际接口另测。所有结果路径必须为绝对路径，
已有结果拒绝覆盖。快照包含editorHelper.js、markdownEnvironments.js、
latexTheorems.js及欢迎页index.js。

`dom.cjs <7..10> <before目录> <新结果JSON>`通过已有Playwright和本机Chrome
在离线headless页面运行自有代码，保留Chrome沙箱。分别核对标题解析临时数组、
引用候选祖先查找、嵌套逻辑文本区剪枝、通知合并及页面退出后的停止。标题／
链接／上下文偏移／保护字节和源HTML恢复必须一致。DOM数组和API调用减少不
等同于进程RSS或整App速度下降。

欢迎页的合并只用于数据库通知：同一刷新函数至多一个通知触发的执行和一个
待处理尾刷。显式用户操作仍等待原有函数，正在保存的任务不会被取消。失败
记录后允许下一次通知重试；非缓存pagehide取消尚未启动的计时器。

执行时不要启动正常客户端、使用固定用户资料、访问网络或禁用保护。真实
编辑器合成验证、双PDF和逐轮返回顶层事件循环的原生内存对照单独留证；
不重复数据库／归档／全组件矩阵，不用强制GC、清缓存或销毁共享profile造收益。
