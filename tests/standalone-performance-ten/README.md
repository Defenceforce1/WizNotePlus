# Bounded ten-round performance campaign

Owned source only, synthetic strings/DOM and disposable local fixtures. Each
round keeps its immediate pre-change source snapshot locally and compares the
same outputs before measuring the isolated operation. No real notes, account,
clipboard, network service, foreground window or vendor internals are used.

The planned rounds are: streaming code-block masking; TeX scanner tail copies;
entity encoding temporary arrays; theorem replacement copies; theorem overlap
lookup; theorem DOM offset lookup; reference-context object count; repeated
heading parsing; completed thumbnail request admission; obsolete welcome task
parameter requests. A round without confirmed benefit is recorded as retained
or rejected, never counted as an implemented optimization.

String/operation counts and microbenchmark times are not whole-client speed,
resident memory or leak-freedom claims. Final related native-reader mode/source
checks and a bounded valid-graphics lifecycle run remain separate acceptance.

All ten rounds are now implemented with 1228 local assertions. The final
associated matrix adds 748 assertions (1976 total); repeated baseline runs are
not added. Each phase238 local snapshot is private evidence, not a new test user
directory. The real editor/theorem and PDF checks are separate from these
synthetic providers. See `docs/performance-ten-2026-10-24.md` for limits.

The linked thumbnail fixture must have the normal local SQL resource layout;
missing schema files exposed a pre-existing null close during failed-open
teardown. The small `thumbnail-main.cpp` also checks the unopened manager path.
It is linked separately from existing production objects, never normal main,
and the original fixture creates its own temporary database and settings.

The `retention-yield-editor` reader diagnostic keeps one isolated persistent
profile, returns to the top-level event loop between each 6000-paragraph,
128-formula reading/editing/close round, and records widget/window/profile-child
release. It does not force GC, clear caches or insert explicit autorelease
pools. Nested stress timing is not a native-retention comparison.
