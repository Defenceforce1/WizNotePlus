# Markdown 导出恢复接口规范（v1）

状态：接口冻结；第 113 轮授权离线回归完成，实验接入仍默认 OFF，原生／真实资料门槛未完成  
日期：2026-10-20  
适用范围：用户主动导出的 Markdown 正文及同名资源目录

本规范把第 70～79 轮隔离模型的结论收敛为产品接入边界。配套机器契约位于
`tests/standalone-markdown-export/recovery-interface-contract.json`；规范和契约冲突时，
不得静默选择其中一方，必须先修正冲突并重新通过契约校验。

## 1. 目标与非目标

目标：

- 普通失败继续保持当前事务语义：旧导出完整保留，或新导出完整提交。
- 应用被强制终止后，只针对用户正在再次访问的同一导出目标发现恢复现场。
- 未经用户明确确认，不改变、不清理恢复现场。
- 恢复前重新核对实时文件状态，任何缓存都不能授权覆盖。
- 恢复日志仅保留解释决策所需的最少信息，并与目标恢复锁完全分离。
- 退出时不阻塞本地笔记保存，不改变既有三秒同步策略。

非目标：

- 不在应用启动时扫描文件系统或历史导出目录。
- 不自动恢复、自动删除或按时间猜测恢复现场是否过期。
- 不用持久化摘要缓存决定是否覆盖文件。
- 不处理第三方专有组件、远程服务、身份验证、更新或安全机制。
- 不把隔离模型中的故障注入和性能探针直接带入正式运行路径。

## 2. 所有权与路径

对目标 `/parent/note.md`，目标身份是其规范化父目录和文件名编码后 SHA-256 的
前 24 个十六进制字符。恢复目录和目标锁都位于目标父目录：

- 恢复目录：`/parent/.wiz-export-recovery-<identity>`
- 目标锁：`/parent/.wiz-export-lock-<identity>.lock`
- 清单：`<recovery>/transaction.json`

恢复目录权限为 `0700`。目录、清单、目标、资源目录或中间目录只要是符号链接，
都拒绝恢复并保留现场。清单中的 `destinationName` 和 `resourcesName` 只能是 basename，
不得含 `/`、`\`、`.`、`..` 或任何父目录跳转。

确定性恢复目录只解决“同一目标能够再次找到现场”，不构成目录归属证明。每次操作仍须
校验清单、目标身份、文件类型和实时摘要。

## 3. 清单 v1

清单采用 UTF-8 紧凑 JSON，只允许以下字段，不接受未知字段：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `schema` | integer | 必须为 `1` |
| `destinationName` | string | 安全 basename |
| `resourcesName` | string | 安全 basename |
| `oldMarkdownExisted` | boolean | 旧正文是否存在 |
| `oldMarkdownSha256` | string | 存在时为 64 位小写十六进制，否则为空 |
| `newMarkdownSha256` | string | 64 位小写十六进制 |
| `oldResourcesExisted` | boolean | 旧资源树是否存在 |
| `oldResourcesSha256` | string | 存在时为完整树摘要，否则为空 |
| `newResourcesExisted` | boolean | 新资源树是否存在 |
| `newResourcesSha256` | string | 存在时为完整树摘要，否则为空 |

清单先通过同目录原子替换提交，再同步清单文件、恢复目录及其父目录。资源改名、正文提交、
回退改名和最终清理后，同样执行文件或目录及相关父目录持久化屏障。

清单不记录可直接执行的绝对路径，也不以一个可伪造的 `state` 字段决定动作。恢复状态由
清单声明和实时正文、资源目录、`previous-resources`、`returned-resources` 的受限组合共同推导。
识别的证据状态为：准备完成、旧资源已保留、新资源已安装、正文已提交、回退新资源已返回、
回退旧资源已恢复。任何其他组合均拒绝并保留。

## 4. 触发与操作接口

只允许两个发现入口：

1. 用户再次导出到同一目标；
2. 用户明确打开该目标的恢复详情。

发现接口不得修改恢复目录：

```cpp
enum class WizMarkdownRecoveryAvailability {
    None,
    AwaitingDecision,
    Busy,
    Refused
};

struct WizMarkdownRecoveryInspection {
    WizMarkdownRecoveryAvailability availability;
    QString destinationIdentity; // 24 位身份摘要，不是完整路径
    QString userVisibleSummary;
    QString diagnosticDetail;    // 仅在用户打开详情后展示完整路径
};

WizMarkdownRecoveryInspection inspectMarkdownExportRecovery(
    const QString& destination);
```

决策接口把恢复结果和审计结果分开报告，防止“恢复成功但结果日志失败”被误报为文件回退失败：

```cpp
enum class WizMarkdownRecoveryDecision { Inspect, Cancel, Retain, Confirm };
enum class WizMarkdownRecoveryOutcome { None, RolledBack, Finalized, Busy, Refused };
enum class WizMarkdownRecoveryAuditOutcome { NotRequested, Recorded, Failed };

struct WizMarkdownRecoveryResult {
    WizMarkdownRecoveryOutcome recovery;
    WizMarkdownRecoveryAuditOutcome audit;
    QString userVisibleSummary;
    QString diagnosticDetail;
};
```

`Inspect`、`Cancel`、`Retain` 都不改变恢复现场；`Cancel` 与 `Retain` 的文件效果完全相同。
`Confirm` 是唯一允许进入恢复写路径的决策。

## 5. 确认恢复顺序与锁规则

确认恢复严格执行以下顺序：

1. 获取审计锁，追加 `confirm/requested` 意图，持久化并释放审计锁；
2. 获取目标锁；
3. 在目标锁内重新读取严格清单，并重新摘要所有相关实时内容；
4. 对识别状态执行回退或完成，未知状态拒绝；
5. 持久化结果并释放目标锁；
6. 重新获取审计锁，追加最终结果，持久化并释放审计锁。

审计锁和目标锁永不嵌套。写入意图失败时不开始恢复；文件恢复已经完成后，最终审计写入失败
只单独报告 `audit=Failed`，不得尝试制造第二次文件回退。

目标锁和审计锁均拒绝：活动所有者、符号链接、畸形记录、外地主机或其他程序的记录。
默认不清理死亡锁。只有用户已经确认恢复，且锁同时满足“同机、同程序、PID 明确不存在”时，
才允许显式接管；接管后仍要完整重读清单和重算摘要。

## 6. 保守恢复规则

- 正文已匹配新摘要时，资源也必须精确匹配新状态；随后仅完成清理并报告 `Finalized`。
- 正文仍匹配旧摘要时，只在旧资源备份、新资源和中间目录组合全部可解释时回退，报告
  `RolledBack`。
- 当前正文或任何资源树出现外部改写、字段不完整、摘要不匹配、未知目录组合或链接替换时，
  报告 `Refused` 并保留全部现场。
- 锁被活动进程持有或不能被明确判定为本机同程序死亡进程时，报告 `Busy`。
- 持久化摘要缓存即使格式正确也只能减少诊断成本；首次使用仍必须从磁盘重算，恢复授权只来自
  目标锁内的实时摘要。

## 7. 审计日志生命周期

审计日志属于应用私有数据，不属于导出目录：

- 根目录：`QStandardPaths::AppLocalDataLocation/recovery-audit/v1`
- 目录权限：`0700`
- 文件权限：`0600`
- 当前段上限：64 KiB 或 256 条，以先到者为准
- 归档上限：2 个
- 事件字段：`destinationIdentity`、`decision`、`event`

日志不写完整路径、笔记标题、正文、资源名、时间戳或内容摘要。由于没有时间戳，不能声称按天数
保留；保留边界只由大小、条目数和归档数定义。

用户可以清空应用私有审计目录。清空审计和卸载都不得扫描导出位置，也不得删除任何恢复现场；
卸载清理最多删除应用自己拥有的审计根。

## 8. UI、无障碍与退出协调

主提示：

> 检测到上次 Markdown 导出未完整结束。默认将保留现场，不会覆盖现有文件。

操作：

- `查看详情`：打开用户主动请求的详情，可显示完整路径和拒绝原因，不改变文件；
- `保留现场`：默认操作；
- `检查并恢复`：明确确认后才进入第 5 节流程。

不得设置自动倒计时。键盘焦点初始位于“保留现场”，所有操作都有屏幕阅读器名称，状态不能只靠
颜色表达。关闭窗口、按 Escape、退出应用和取消都等价于保留现场。

如果退出开始时提示仍打开，立即收敛为 `Retain`：不修改恢复目录、不阻塞本地笔记保存、不启动
额外云同步、不延长或重置既有三秒退出同步窗口。保留事件仅尽力写审计；写入失败不阻止退出。

第 109 轮明确尽力策略：退出或导航失效时不提交新的审计 I/O，排队中的普通保留记录可取消；
不等待审计结果，也不弹日志失败提示或重试。普通当前上下文选择保留（按钮／Escape／关闭）
可以在原后台队列单次尝试 `retain/retained`，应用收尾信号立即发布，收尾销毁会话也可丢弃记录。
已开始的磁盘调用不能强停，仍由既有线程池正常收尾，不能声称三秒或任何硬性文件 I/O 上限。
这是允许日志缺失的尽力审计，不是每次退出必有持久记录，更不是恢复写入授权。

## 9. 产品接入边界

默认 OFF 的 `WizMarkdownExportTransaction::write` 仍使用随机 `QTemporaryDir`，普通失败会在当前
进程内回退；回退失败才保留临时路径并返回错误。第 111 轮 ON 分支使用确定性恢复目录和 v1 清单，
依次准备、安装资源、最后提交正文；实验接入不代表已启用或整 App 已验收。以下各轮叙述保留
当时的边界，本规范不会把测试模型成功误记为默认产品能力。

第 81 轮已新增 `WizMarkdownExportRecovery.{h,cpp}`，实现目标身份、同级路径推导、复合结果类型和
严格清单的只读查看；独立测试直接编译这两份产品源码。它们尚未列入 App 构建，也没有被当前导出
事务调用，因此仍不构成产品运行能力，且不能写清单、接管锁或执行恢复。

第 82 轮在同一休眠核心中增加确认前预检：没有既有锁时原子取得保守目标锁，在锁内重读严格清单、
重新计算正文／资源摘要并分类六种证据状态。预检只返回 `RollBack`、`Finalize`、`Busy` 或 `Refused`
计划，不执行计划。活动锁保持忙碌，畸形／外地／链接锁拒绝；真实同机同程序死亡 PID 只标记为
`ConfirmedDead`，不自动接管或删除。该核心仍未列入 App 构建。

第 83 轮增加仍休眠的持久化准备器：在没有既有现场且目标锁可用时，先记录并同步旧状态，再创建
`0700` 的确定性恢复目录、暂存新正文和 HTML／资源，重新核对旧状态未变化，最后以 `0600` 原子提交
严格 v1 清单。准备器不替换实时正文或资源；普通失败只在目录身份仍属于本次调用时清理自己的私有
现场。真实子进程在清单提交前终止时会留下无清单现场和死亡锁，普通重试保留二者。该核心仍未列入
App 构建，且尚未覆盖清单提交与各目录同步之间的全部终止窗口。

第 84 轮收紧已提交现场的结构所有权：用于提取资源的暂存 HTML 必须在提交清单前删除并同步；恢复
目录只允许 `transaction.json`、`new-markdown`、`content`、`previous-resources` 和
`returned-resources`，前三项必需，`content` 只允许清单声明的资源目录。资源目录在已知改名步骤后
可以离开 `content`，其他额外条目、链接或错误类型一律拒绝并保留。真实子进程在完整清单提交并释放
锁后被终止，重新查看仍识别为待决现场，预检仍识别为 `prepared`，实时旧正文／资源未变化。该核心
仍未列入 App 构建，尚未执行任何回退或完成改名。

第 85 轮增加仍休眠的 `executePlan` 原语：调用者只能传入先前预检得到的 `RollBack` 或 `Finalize`，
执行器取得保守目标锁后在每个改名／清理步骤前重读严格清单、复核恢复目录身份并重算实时摘要；计划
已经变化时拒绝。目录改名后同步源和目标父目录，最终清理前同步预期旧／新实时状态并再次确认同一
终态。六种已知状态、首次导出、无资源、外部改写、活动／死亡锁和重复调用均由直接编译产品源码的
测试覆盖。该原语不写审计，返回 `audit=NotRequested`，不能代替第 5 节的确认编排，仍未列入 App
构建或当前导出事务。

第 86 轮只在独立 `markdown-recovery-core` 测试目标中编译故障检查点，用真实子进程覆盖：新资源返回
后但父目录同步前、旧资源恢复后但父目录同步前、终态复核后清理前、恢复目录删除后但父目录同步前。
前三种终止在测试显式清理自身已确认死亡锁后，可重新识别并幂等续做；最后一种没有可见恢复目录，
实时旧状态完整，但死亡锁会继续阻止新导出。正式源码未定义测试宏时不包含等待或就绪文件逻辑，默认
路径仍不接管死亡锁。这些结果不代表存储掉电安全。

第 87 轮增加显式 `takeOverConfirmedDeadDestinationLock` 构件，普通查看、预检、准备和执行均不调用。
它只接受同机、同程序且 PID 已不存在的普通锁文件；在 Unix/macOS 上以不跟随链接方式打开，二次核对
所有者，并要求删除前的设备号／inode 与已打开文件一致，随后删除并同步父目录。活动、畸形、外地、
链接或核对期间变化的锁均保留。接管只返回锁结果，不返回恢复成功；测试在接管后重新执行严格预检，
再调用计划执行器。有恢复现场和没有现场的遗留死亡锁均已覆盖，但用户确认和审计意图仍未接入。

第 88 轮完成仍休眠的独立审计意图核心 `appendConfirmIntent`：固定私有应用位置、独立锁、规范三字段
JSONL、原子整文件提交和文件／目录同步；只有释放审计锁并确认目录同步后返回 `Recorded`。未知、
截断、重复字段或超限日志保留并拒绝；本轮仅支持 `confirm/requested`，不自动轮换。测试宏仅在独立
目标中重定向至临时应用数据目录。结果事件和确认编排尚未实现。

接续复核发现旧目标锁的 `release()` 未向调用者报告失败。第 90 轮已补齐准备／预检／执行的独立
`lockRelease` 结果及故障回归：失败时预检拒绝可执行计划，准备保留现场；已完成的文件恢复结果保持
真实，同时明确解锁未确认。未来确认编排必须检查该字段，不能只看文件恢复枚举就报告整体成功。

第 98 轮增加仍休眠的 `appendConfirmResult` 窄片。只接受恢复结果枚举，输出
`confirm/{none,rolled-back,finalized,busy,refused}`；不写诊断文字，不改变三字段格式或私有权限、
64 KiB／256 条上限。目标锁释放失败或未知时拒绝；文件已回退／完成却未确认释放时也在审计 I/O 前
拒绝。结果函数不执行恢复、不改变独立恢复结果；结果写入忙碌或失败后，完成的文件状态保持不变。
调用者仍须保证目标锁已经释放，该函数不是锁顺序编排器，也不凭结果事件授权文件恢复。
日志有限轮换、意图与结果的确认编排、UI／无障碍和退出协调仍未实现，仍未列入 App 构建。

第 100 轮在仍休眠的产品审计核心中实现有限轮换：当前 `recovery.jsonl` 加 `.1`、`.2` 两个归档，
每段仍最多 64 KiB／256 条。持独立审计锁先严格检查所有保留段，拒绝损坏、超限、空归档、链接、
非普通段及未知同前缀文件；每次删除／移动前复核字节和文件身份。只有正常连续段，或“完整当前段
加唯一 `.1` 缺口”的已知中断移位才能继续；后者不再次丢弃已移入 `.2` 的保留段。
各改名／删除后同步目录，再以私有 `QSaveFile` 提交新当前段并同步文件／目录，解锁确认后才返回
`Recorded`。归档有效权限不私有时先收紧并同步，不更改事件字段。产品仍不自动删除死亡审计锁；
七个真实子进程终止边界在测试明确移除自身死亡锁后重新验证、续做。

轮换不是三个文件同时原子提交。失败可能保留已解释的移位状态，提交后的失败也可能已有事件，
不宣称同一请求恰好写入一次；上层不能以日志失败回滚已完成的文件恢复。当轮尚无正式死亡审计锁接管、
确认编排、UI／无障碍或退出协调，仍未列入 App 构建。测试终止不等于存储掉电验收。

第 101 轮补齐显式 `takeOverConfirmedDeadAuditLock` 构件，普通追加不调用。只有同机、同程序且
PID 明确不存在的普通自有锁才可删除；没有目录／锁时不创建目录或日志，目录形状／归属异常则拒绝。
打开审计目录及旧锁后，非阻塞文件互斥串行化合作接管；再次检查目录／锁设备号、inode、锁字节及
死亡状态，只在核对一致后删除该目录内的锁并同步目录。活动写者、其他接管、未知所有者及核对期间
变化的锁／目录均保留。删除或同步未确认时独立返回 `Failed`，锁可能已经不存在，调用者必须重查。
