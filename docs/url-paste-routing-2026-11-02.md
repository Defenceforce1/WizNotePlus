# URL 粘贴的附件分流修正

网页链接有时同时携带 text/uri-list。旧附件入口直接把每个 URL 转为本地路径，
HTTP 等非文件 URL 得到空路径，随后触发“不能添加0字节的文件作为附件”及空文件名。

修正仅在附件入口增加本地文件与非空路径条件。普通网页／邮件等链接交还原有文本／
HTML 粘贴流程；实际零字节本地文件继续显示带文件名的提示。本地附件、图片及混合
URL 列表既有分流保持，正文读取许可和失效检查不变。

必要验证：

- 从实际两个方法提取的 Qt 回归共36项：旧实现9项失败，修正后全部通过。
  包括 URL MIME、空路径、真实空文件、图片、附件、混合列表、撤销读取许可和阅读模式。
  剪贴板与附件数据库使用隔离替身，没有读取系统剪贴板。
- 当前主程序源码编译链接后，三个合成编辑／撤销重做／保存／ZIW归档回读通过，
  12次非本地或空URL拒绝均无附件副作用，普通笔记内图片字节保持；合成URL正文回读一致。
- 没有执行物理剪贴板粘贴验收，也未修改安装中的App或真实笔记；修正尚未打包。

首字丢失另行定位：用户确认 Caps 切换 ABC／Fcitx5 后立即输入时，Qt 原生输入框正常，
同进程空白 WebEngine 网页仍会丢首字。它不依赖笔记富文本编辑器内容；但该对照仍有
应用级过滤器，不能据此认定某个上游缺陷。没有合入延时、补发按键或强制重置焦点。
