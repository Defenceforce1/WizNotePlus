## 已用堆不足以直接解释全部高水位

第三组第6次大文档读取后的数值，约为：JS已用26.97MiB、JS总堆99.58MiB、接口报告的
嵌入器已用74.40MiB、backing storage10.98MiB；原生footprint约477.69MiB。
切小后JS已用约38.17MiB、嵌入器已用75.39MiB，footprint约479.67MiB。
自然空闲后JS已用约10.13MiB、JS总堆约11.44MiB、嵌入器已用约1.12MiB、
backing storage约5.18MiB，footprint约81.50MiB。

不能将这些类别相加减来算出某分配器的“剩余泄漏”：口径、覆盖范围、共享／重叠及
采样时点不同。嵌入器数值也不是所有DOM、布局、GPU或原生分配的完整归属。它们
说明单看JS已用堆或当前元素数不足以解释物理高峰，也说明对象与总堆有自然回落；
尚不能区分每一块活动原生分配、可复用容量与碎片，不具备直接改动上游的依据。
