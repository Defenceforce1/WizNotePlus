# 第六十四轮：单按钮信息提示与调用者同时保护

2026-10-19，14.4.21 开发源码；仍暂停打包、部署／签新副本、安装，不操作真实业务或资料。

审阅 17 处默认单 OK 的 information 调用，发现五处提示后的界面操作需要所属对象检查：邮件错误标签、证书输入的三处焦点恢复、主窗口同步后的界面更新。其余直接结束或返回；两处购买相关多按钮 information 不在本次范围内。

先做两种独立失败对照，均只终止自己的诊断进程（134）：

- 当前旧 information helper 在合成父窗口销毁时，ASan 报栈消息框错误释放。
- 用测试专用动态 helper 副本绕过前一问题后，**提取的旧邮件错误槽函数＋合成 UI 外壳**又复现后续访问已释放界面的 heap-use-after-free。这不是实际邮件窗口／网络流程，也不是把全局实验 helper 装进 App。

因此同时修改：只有 information 且按钮集合恰为 OK 才加入既有动态弱所有权分支；五处后续 UI 动作增加弱指针检查，同步 UI 还复用已有退出标志。普通存活窗口行为、提示内容／图标／按钮／默认及翻译不改，购买／确认和其他按钮集合不改。没有取消保存确认、改变同步策略或新增退出提示。

## 验证

- 当前实际 helper 普通 **24 项**，information／critical／warning 所属窗口销毁各 **3 项**，分别在 ASan／UBSan 下连续五轮通过。
- 配置时提取当前实际邮件错误槽，实际 helper＋合成外壳的存活更新 **3 项**和销毁返回 **3 项**也各连续五轮通过。只覆盖提取方法的相关边界，不冒称邮件对话框构造、网络或其他业务调用链端到端。
- 主程序重新编译，完整 **20 组／843 项通过，125.91 秒**。主程序未加 ASan；独立检查中 Qt 自身未插桩、泄漏检查关闭。离屏图形诊断保留，未新验收原生前台／PDF 几何／Metal 压力。
- 四个产品文件逐字节与修改前比较，只含预定条件、存活检查及 include，原 BOM／CRLF 保留。初次新诊断目标缺少 QAbstractButton 完整类型头文件，补齐后编译；失败记录保留，不是产品编译故障。

全局动态原型仍未接入。其他按钮集合、外层堆栈对话框、构造／业务完整链路及进入消息框之前的旧式延迟回调仍单独评估，不能把这些局部通过当成所有模态问题已经解决。尤其登录服务器超时的原主队列闭包仍直接捕获窗口，下一步单独核查，不在本轮顺带扩大改动。
