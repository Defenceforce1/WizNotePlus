# 第二十二轮：持续构建、窗口稳定观察与图形分配证据

2026-10-18。本轮不安装、不更换现用组件／图形后端，不改编辑器、笔记格式、同步、账号、目录或图标。产品实现未改，仅加强原生窗口诊断；引擎源代码保持未修改的基线，PDF 定位补丁尚未应用。

## 提前修正单架构构建配置

继承的通用 Qt SDK 将 `QT_IS_MACOS_UNIVERSAL` 默认设为 ON；仅指定 `CMAKE_OSX_ARCHITECTURES=arm64` 仍会让模块走通用链接分支，最终引用没有构建的 `Release/x86_64/*_libs.rsp`。本轮在链接前发现并显式设为 OFF，生成的 Core／convert_dict 响应文件路径均转为 arm64，走正常单架构链接。没有伪造 Intel 文件、修改 SDK／引擎源码或无谓编译第二种架构。

原有对象保留、增量继续。当前 32 GiB 机器的内存压力查询健康，编译子进程占用较低，因此从三任务提高到**最多六个嵌套编译任务**，外层最多两个，保持 nice=10；继续监控，不能把这个数字无条件套用于其他机器或重负载阶段。任务范围内临时阻止空闲休眠，构建结束释放，不改系统休眠偏好，不保证合盖／关机后继续。

检查点仍为编译中，尚无完整可运行的自编译引擎或补丁 PDF 结果。SDK 27 与 Qt 测试 SDK 26 的警告保留，不等于完成新版系统兼容验收。编译完成后先确认自编译原版能复现现用 SDK，再分别验证补丁，不绕过完整原版对照。

## 原生窗口：延迟重排不能被单帧绿灯隐藏

`tests/compat/mac-window-controls.mm` 新增显式 `WIZNOTE_TEST_HEADER_ONLY=1` 的专项模式和只读 `WIZNOTE_TEST_HEADER_TRACE=1`。专项输出明确不是完整回归；只跳过无关编辑／搜索步骤，仍使用实际主窗口、临时合成账号／数据库、禁用同步及远程访问。记录 Qt／AppKit 状态、焦点和标题容器几何，不修改原生 frame、事件或产品实现来获得通过。

还将四个原有对齐检查加强为**连续 500 ms 满足原误差范围**，避免显示／状态切换后的一个事件循环瞬间匹配就过关；默认检查标签／数量保持。可额外设置 `WIZNOTE_TEST_HEADER_REOPEN_CYCLES=10`，最多 20 次，只增加诊断动作。

## 内存：先取得分配种类，不盲目改默认图形设置

Xcode 的 Allocations 仅尝试启动独立合成 Qt 探针，没有选择其他应用或系统全进程。实际启动注入未进入探针 main；到时报告 failed to attach，返回 2，采集无效。检查发现 Developer Tools 授权关闭，但不能仅凭这点断言附加失败唯一原因。没有开启授权、改变系统保护、修改签名或把失败记录算作内存测试成功；失败 trace 与启动采样只留本机。

改用本机 `malloc`／`malloc_history` 手册记录的 `MallocStackLogging=vm`，仅在独立测试进程／后代环境中开启，不影响主 App。`vmmap -summary` 和 `malloc_history -allBySize` 均成功读取这一个合成进程；没有读取分配内容或用户笔记。探针仍使用原有十批／40 次临时页开关，**64 项**检查通过并清理临时 profile。

这次带 VM 记录的运行，首／末关闭批次的本进程 RSS 约 **188.83 → 190.66 MiB**，系统 footprint 约 **201.94 → 629.16 MiB**，再等十秒约 **611.92 MiB**。记录器可能扰动时间和占用，不能直接拿它替代之前无记录器的基线数字。

## 纹理所有权线索尚不是安全补丁

现用 SDK 的精确 WebEngine 模块源码中，[Metal 输出设备](https://github.com/qt/qtwebengine/blob/8c73295524f3ce6a2e10ad2f71141c695376c876/src/core/compositor/native_skia_output_device_metal.cpp) 把上次导入的纹理延迟交给 buffer 清理回调，但最后一次纹理保留于裸指针，析构为空；正常 `hasResources` 又只检查 buffer 回调。它与当前表面增长现象相符，是待验证的所有权缺口线索。

不能直接在页面关闭时强制释放这个指针：[对应 Qt Declarative](https://github.com/qt/qtdeclarative/blob/95549d7db3344829d4e89c5533a7bd98dbaa1dd7/src/quick/scenegraph/util/qsgplaintexture.cpp) 不接管导入纹理的原生所有权，[对应 Qt Base 的 Metal RHI](https://github.com/qt/qtbase/blob/5a1194b2d368e2d72c230205c464b04a2f23eccd/src/gui/rhi/qrhimetal.mm) 又采用不自动保留资源的 command buffer。过早释放可能造成 GPU 使用已释放对象；需要联合 QSG／RHI 包装器生命周期、命令完成和隐藏／关闭窗口验证，不以单纯让 footprint 下降作为安全性证明。

本轮没有应用这样的内存补丁，也没有关闭硬件加速、主动 GPU 等待或清理用户缓存。PDF 底层重编译可以作为之后隔离验证小范围引擎候选的基础，但原版、PDF 候选与内存候选必须分开比较，不混成一个无法归因的改动。

所有用户文件、运行日志、VM 栈、trace、截图和完整引擎源码／输出只留本机。只经 GitHub 插件备份诊断源码和脱敏记录，稳定分支不动，现用／冻结／已交付包保持原样。
