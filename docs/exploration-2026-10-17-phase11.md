# 第十一轮：原生多页内存归因

日期：2026-10-17。仅增强隔离测试与分析工具，**没有修改产品运行策略、升级编辑器、关闭硬件加速或安装应用**。现用 App 只读观察为 14.4.17，已交付的 14.4.18 候选和冻结的 14.4.16 保持不变；本轮不为测试工具变动另发安装包。

## 为什么继续测量

此前虚拟可见数学页关闭后 RSS 增长，空白页增长较小，但不能据此证明公式引擎泄漏。本轮增加真实 Cocoa 窗口、单一宿主窗口、主事件循环和图形后端对照，同时测量本进程 `task_vm_info.phys_footprint`。该系统计量与 RSS 不同；RSS 小幅变化不能排除图形资源增长。

仍使用原 mac 客户端引擎、实际 QWebChannel 和临时合成数据，每批四页，每页 16 个公式。逐页核对完整 Markdown 和公式数，关闭后核对视图、页面 QPointer、子进程和剩余窗口控件。所有外部请求被拦截，成功运行要求没有外部请求。不读取真实账号／笔记，只统计本次进程树，不采样其他应用的内存内容。

## 测试工具改进

- Cocoa 可见性必须通过独立测试参数明确开启；原 offscreen 参数在 Cocoa 下仍拒绝运行，避免误开真实窗口。
- 单宿主模式在一个 900×600 点窗口的 2×2 布局中反复创建／关闭四页，比每批新建四个顶层窗口更接近标签页负载；并非完整主窗口、资料列表或同步负载。
- 批次之间返回实际 `QApplication::exec()`，再等待 100 ms 进入下一批；保留同步嵌套循环对照。两者本来就不是同一种窗口负载，不能拿差值宣称产品优化百分比。
- 增加本进程 RSS、系统 footprint、internal／external／compressed 计量及控件数；关闭一秒后采样，结束后再等十秒采样。不主动清缓存、强制 GC、丢弃撤销历史或卸载用户笔记。
- 批次数限制 1—30。新增 `summarize-editor-memory.cjs`，拒绝失败、不完整或仍有子进程的日志；分别输出 RSS／footprint，不自动给出“无泄漏”结论。

## 本机实测

Qt 6.11.3，Apple Silicon，Cocoa；默认图形日志确认为 Metal。软件对照日志确认为 `Loading backend software`。下表为每批关闭四页、等待一秒后的本进程数据（MiB），首批含暖机。

| 测试 | 页打开次数 | RSS 首／末 | footprint 首／末 | 再等十秒 footprint |
| --- | ---: | ---: | ---: | ---: |
| 单宿主、Metal、数学 | 120 | 202.61／207.02 | 156.36／398.27 | 367.13 |
| 单宿主、Metal、空白 | 40 | 204.28／205.55 | 160.14／282.58 | 256.05 |
| 单宿主、软件渲染、数学 | 80 | 207.78／208.63 | 95.31／92.38 | 92.25 |

三组分别通过 61／21／41 条命名检查；数学组每页源码和 16 个公式均符合预期。各批关闭后进程树均为 1，控件均为 1（保留的宿主），profile 后代对象数均为 0；视图和页面已释放，外部请求为 0。

另做了十批四顶层窗口的数学／空白对照，以及返回主循环的顶层窗口对照。其增长显著受到窗口结构和事件循环方式影响；旧虚拟窗口日志还包含图形 mailbox 警告。因此不能用此前 RSS 曲线直接评价日常 App，也不能把测试工具修正称为产品泄漏修复。

一次仅针对本次隔离进程的 `vmmap -summary` 快照同时出现 IOSurface、owned-unmapped graphics 等图形资源；快照并非堆栈分配归因或单一根因证明。原始诊断含环境路径，仅保留本地，不上传 GitHub。

## 结论与未完成

1. 在已测负载中，关闭后不是四个笔记页面／渲染子进程继续存活；只有 RSS 也会漏掉重要增长信号。
2. 空白页也可复现，软件后端未复现相同持续增长，**支持下一步优先检查 Qt 原生图形／Metal 资源生命周期**。尚未锁定具体代码行，也不能排除缓存、延迟回收或本机平台因素；不可直接声称修复了泄漏。
3. 不将软件后端设为产品默认：本轮没有完整验证其绘制质量、滚动、视频、PDF、功耗及 CPU 成本。它仅是诊断变量，不是用户应当采用的设置。
4. 120／80 次页开关是有限合成负载，不是完整 App 长期使用或所有机型验收；尚需核对实际标签页／保留当前页时的资源回收，再选择最小风险改动。
5. 编辑习惯、笔记格式、MathJax、CSS、撤销历史、同步／本地保存和现有 PDF 路线均未改；PDF 引用位置问题仍开放。

## 重现

仅对带兼容测试入口的独立开发构建运行，不正常启动账号窗口。先关闭其他本项目合成窗口测试，顺序执行以下对照；实际 Cocoa 模式会显示合成窗口，完成后自行退出。

```sh
env QT_QPA_PLATFORM=cocoa WIZNOTE_MEMORY_VISIBLE_COCOA=1 \
  WIZNOTE_MEMORY_SHARED_HOST=1 WIZNOTE_MEMORY_BATCHES=30 \
  QSG_INFO=1 /absolute/development/WizNotePlus --editor-memory-probe
```

空白对照加 `WIZNOTE_MEMORY_EMPTY_CONTROL=1`，软件对照加 `QT_QUICK_BACKEND=software`。顶层窗口对照不设 `WIZNOTE_MEMORY_SHARED_HOST`；旧同步循环只在显式设置 `WIZNOTE_MEMORY_NESTED_LOOP_CONTROL=1` 时使用。不要把诊断参数写入正式 App 的启动设置。

```sh
node tests/compat/summarize-editor-memory.cjs /absolute/probe.log
```

本地证据为 `outputs/exploration-20261017/phase11/` 的合成测试日志与汇总；不把私有数据、原始进程内存或诊断环境路径作为公开备份。
