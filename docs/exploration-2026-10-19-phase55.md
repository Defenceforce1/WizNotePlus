# 第五十五轮：Markdown 导出写入顺序的隔离复现

2026-10-19。仅新增诊断工程与记录，主程序源码不变；继续暂停打包、部署、签新副本及安装。

独立 Qt 工程在配置时从当前源码提取实际 `saveAsMarkdown(QString&, bool)` 方法、三参数 UTF-8 写入函数及文件名工具，执行实际浏览器 JavaScript 回调。只替换类限定名／写入函数名以接入合成适配器。数据库协作者是明确标注的模型：写入合成 HTML 后返回成功，或模拟后续资源复制失败；没有链接实际数据库、档案读取、主窗口或账号。

所有文件位于自动清理的临时目录，浏览器使用离线临时 profile，外部请求被拦截；SDK 资源在浏览器启动前做绝对路径可读性检查。没有使用真实笔记、覆盖用户导出文件或触及安装副本。

## 结果与限制

- 常规诊断 **40 项，连续五轮通过**：取消输出选择不写入、Unicode／合法空笔记／资源路径替换／无 BOM 字节，以及真实回调完成与一次调用均有断言。
- 这不是安全验收：“通过”表示复现了旧顺序。浏览器回调前，已有合成文件已经被 HTML 替换。`undefined`、`null`、异常返回随后被写为空文件，数字被转成字符串写出。
- 显式安全对照 **45 项中 5 项失败**，进程正常返回 1：四种无效结果未保留已有文件，加上模型中的后续数据库失败留下 HTML。失败证据保留，不把它写成已修好。
- 错误 SDK 路径控制返回 2，未启动浏览器。

这是当前导出方法的**提取源码流程测试**，不是实际 `WizDocumentWebView`／数据库／资源复制端到端测试。模型失败不证明真实档案复制已经失败；本轮也未进行新的全主程序回归、原生前台、PDF 几何或 Metal 验收。上一轮完整 20 组／836 项仍只属于上一轮产品源码。

下一步先验证“取得有效的字符串正文后再触及输出”的保护；合法空字符串必须继续支持。资源目录与最终正文的失败恢复还需要单独验证，不把仅修类型判断称为完整事务导出。笔记资料库、原编辑／数学／CSS／PDF、三秒连续无进展退出及图标均不改变。
