# 第四十二轮：服务器地址缓存的归属与并发快照

2026-10-19，14.4.21 开发源码；仍不打包、不部署、不签新副本、不安装，原 App／图标／资料目录保持不变。

## 原实现的实际对照

此前列为待审的全局服务器／缓存状态已进一步核查。新增测试直接调用实际 setEnterpriseServerIP、syncUrl 和缓存路径：先预热合成服务器 A 的地址，再切换 B。旧实现仍返回 A 的缓存地址，“换服务器必须失效旧缓存”断言失败；其余检查正常，初轮网络 73 项中一项失败。此控制仅在内存操作 .invalid 合成地址，严格确认缓存命中后才调用 syncUrl，没有对这些地址发网络请求。

原源码还在缓存锁内执行端点发现及其网络事件循环；仅给 setter 加锁会带来跨线程阻塞。因此没有采用只加一把大锁的修补。

## 修补范围

- 服务器、语言和代际在短锁内取一致快照；URL 仍使用原命令、参数、产品／客户端协议及认证方式。
- 同一标准化服务器重复设置不丢缓存；确实换服务器或语言才使旧缓存失效，空输入仍拒绝且不改变状态。
- 请求与所有后续回退始终沿用本次上下文。旧请求可以完成其原服务器的结果，但不能写入新服务器／语言的缓存。
- 网络 I/O 和 JSON 解析不持全局状态锁；回写时检查代际。同一代际已有端点时，重叠发现不覆盖先前已提供的缓存。
- 登录、头像、邮件及编辑状态等旧入口使用同样的上下文归属；没有启用团队功能或改变服务地址格式。非对象／非字符串的端点数据不强制转成地址。

第一轮编译检出漏更新的 systemAvatarUrl 私有缓存调用，已补齐上下文后重新构建；失败日志保留。源文件 CRLF／BOM 格式保留，使用允许 CR 行尾的临时差异检查，不改仓库配置，不将格式检查输出冒充功能错误。

## 验证

网络安全专题由 69 增至 **86 项**，最终连续五轮通过。新增覆盖：

- 服务器标准化、旧缓存失效、旧代际／旧语言拒绝回写及正常缓存命中。
- 两个实际临时 HTTPS 回环服务器：A 回复期间切换到 B，A 的在途结果保持属于 A，随后 B 单独发现自己的地址；旧结果没有污染 B，缓存命中不新增请求。
- 在实际网络等待时，另一个线程能够取得状态锁，避免递归 GUI 锁掩盖“跨网络持锁”。
- 同代际重叠发现保留已供应端点，且请求数量符合预期。
- 四个线程在服务器／语言反复变化时构造 **1000 个实际 URL 快照**，服务器、语言、命令及产品字段均内部一致；此阶段不联网。
