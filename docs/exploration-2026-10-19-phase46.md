# 第四十六轮：把屏幕共享干扰与原生窗口验收分离

2026-10-19，14.4.21 开发目录。用户要求休息期间持续探索，仍不打包、不部署、不签新副本、不安装、不访问真实账号。所有窗口及资料均为隔离合成夹具。

## 先保留失败，再定位触发源

只增加原生 frame 变化通知和有限调用栈记录，没有替换代理或修改 AppKit 方法。三次独立文档加载／销毁的未捕获窗口对照通过 **108 项／84 步**；接入原生字体面板屏幕操作后，原顶栏失败再次出现，**83 项已执行／58 步，一项失败**。

同步通知捕获的调用链为：窗口共享状态通知 → AppKit 更新共享窗口按钮 → NSThemeFrame 重排按钮。没有经过应用的 Qt resize／windowState 回调。该调用栈是本机诊断证据，不是调用私有 API 的实现方案，也不能单凭它解释全部历史间歇问题。

## 不接受只修正坐标的实验

曾尝试仅观察本窗口原生几何、合并零延迟恢复的窄修补，不轮询、不改代理／动作。坐标恢复了，但原有严格点击命中检查仍失败：首次 **94 项已执行／69 步**，加命中诊断后 **88 项已执行／63 步**，各一项失败。不得把这些称为完整通过。

命中的是 AppKit 新的 ThemeWidgetView 托管容器，而不是原 NSButton 子树。实验性修补已完整撤回，`src/mac/WizMacHelper.mm` 与上一轮备份 blob **8ccb2db7e4f596798cc4c92619dcc376d244034c** 逐字节一致。实验只保留在独立测试目录，明确未接收，主程序不引用它。

## 不含编辑器／数据库的系统对照

新增 `tests/standalone-native-header`：只链接 Qt Widgets 和 AppKit，开发目录独立编译，不含 Wiz 账号、身份、数据库、WebEngine 或正常 profile。`system` 模式不调用任何 Wiz 顶栏函数；其余模式只是可选诊断，不是已接收的产品方案。

`system` 实测在接入屏幕检查前：公共只读属性 `hasActiveWindowSharingSession=false`，原 NSButton 命中成立。接入后该属性变为 true，系统在红黄绿区域显示紫色窗口共享提示，三个原按钮的 NSButton 子树命中均变为 false。一次最小化点击仍落在系统共享提示上，没有把它算作成功。未点击“停止共享”、修改权限、禁用捕获或清理系统缓存。

因此，在这个捕获环境里继续用旧 NSButton 子树断言，不能鉴别产品按钮故障。没有以识别一个私有类名来放宽断言；改为分开两类验收：

- 字体专项显式 `WIZNOTE_TEST_FONT_ONLY=1`，允许操作其原生面板，但结果明确不是完整窗口验收；
- 完整原生几何／命中／动作验收增加“没有活动共享会话”的前提，保留原严格断言，不接入屏幕捕获。

## 最终结果与额外失败

恢复原产品顶栏函数后，未捕获的完整原生测试增加三次真实文档加载／销毁、十次红色关闭重开、二十次 AppKit 重新布局，**179 项／155 步全部通过**；结束时应用激活、窗口验收环境有效，原十一阶段清理提示仍保留，正常退出。

字体专项第一轮与同一应用二进制的后台测试并行，窗口工具遇到 LaunchServices `procNotFound`，未能在期限内操作面板，结果 **38 项已执行／13 步，一项失败**。随后通过正常取消、关闭原保存保护提示和再次正常退出收尾，没有强退。不能把此保护提示当作用户笔记保存失败，也不能隐藏这轮失败。

改为串行、确认仅有一个同二进制测试进程后，字体专项 **42 项／18 步全部通过**，包括四项字体寿命／正文不变检查和本地保存确认。记录明确 `fontOnly=true`、不具备完整原生按钮验收资格。以后操作原生窗口时，不并行运行同一 App 二进制的后台自测。

最终非前台回归 **19 组／768 条命名检查全部通过**，约 117 秒；离屏图形警告原样保留。原始主图标与现用 App 可执行文件 SHA256 均不变。未重新运行 PDF 几何／栅格对照、长期 GPU 或跨机验收；也不声称全部历史间歇顶栏问题已根治。
