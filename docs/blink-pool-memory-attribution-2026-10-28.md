这些是提供者自己的计量名称。allocated_objects_size不是本轮已证明的精确活对象大小；

相比先前只看到V8大区域／标签，此处已具体到Blink GC主堆的池化和已提交类别，是
新的归因证据，但还没有确认分配由哪一个产品操作唯一导致或怎样稳定减少。

## 为什么有依据复查浅克隆

293的浅克隆只测首次打开，约288MiB高于参考约278MiB，所以没有合入。本次新类别
证据指向连续切换中短命DOM分配与池化容量，允许重新检查不同的重复负载，而不是
重新扫描旧参数。候选字节与293完全相同，只在已核许可506的getInnerText中，对
HTML DIV／BODY的直接文字和裸BR输入拼接规范文本、浅克隆根，免去深克隆与HTML
往返。CR／NUL、属性BR、嵌套／其它节点、外来命名空间、is／shadow根仍走原逻辑。
保留292异常清理，不改原文或当前正文DOM，不调整GC、缓存、profile或数学工作量。
