# 组件整合升级收益评测

日期：2026-10-23。区分230相对226的新增变化与之前已经交付的组件升级。
不以版本号、构建通过或DOM数量推断整App性能／真实内存收益。

## 欢迎页实际整合对比

相同Qt6.11.3补丁运行时、1100×800隐藏Cocoa视图、本地实际包内资源，同一合成
传输及少量列表内容，无账号／网络。每组一次预热、五次测量，中位数；浏览器
performance.now从页面导航开始计时，分别记录可见且内容／日历就绪以及其后两帧。
不是进程启动、真实数据库查询、云同步或用户前台感知的整体计时。

| 输入 | 可见就绪中位 | 其后两帧完成中位 |
| --- | ---: | ---: |
| 226实际资源 | 1032.2ms | 1039.0ms |
| 230实际资源 | 17.5ms | 40.1ms |
| 226仅临时去掉固定等待 | 23.0ms | 40.4ms |

归因检查：226自有listEvents在查询前明确等待1000ms，页面显示又等待listEvents。
227待办改为日期提交完成后通知、刷新序列保护，没有这段固定等待。第三组只在
临时合成夹具删除这一条等待，jQuery3.7.1／UI1.13.3／旧i18next完全保持，产品源
和旧App未改。三组各20项计时／加载／隔离检查通过，无外部请求。

结论：整合版确实消除约一秒的人为初始化等待；**主要收益不是jQuery4本身变快**。
对剩余十几毫秒的差距没有独立库级归因或统计显著性结论，不报告“整App快59倍”。
少量合成列表不代表真实大库、登录、同步、内存或实际窗口绘制耗时。
