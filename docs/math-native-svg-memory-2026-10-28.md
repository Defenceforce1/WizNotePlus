## 找到的主要自有触发点

主程序loadDocumentInWeb常规使用load(url)重载文档。已按公开自有C++调用核对，
先前重载夹具适用；没有把未证实的“同一DOM切笔记”假说当作原因。

使用当前196资源、Qt6.11.3／MathJax4.1.3、TeX字体、语义增强关闭。
6000段／128编号公式的同二进制对照，原版约378–381MiB，跳过全部自有fit约283MiB。
只保留BBox及矩形读取也约281–283MiB；说明不必把读几何本身当罪因。
完整批处理仍约380.27MiB、单去viewBox写仍377.05MiB，均不采纳。
分16项让出任务约360.35MiB，也不采纳。没有重写MathJax引擎、降质或强制GC。

实际原生编号SVG的ink为例如x415.06、宽483.38，容器宽900，已在正常范围，
y约-0.00000021属于浮点误差。旧桥却对所有带data-mjx-viewBox而无真实viewBox的全宽
输出都写回固定像素width／height／viewBox及样式。这个不必要的冻结步骤是本轮证实
可消除约100MiB峰值的自有调用点；不声称已识别Chromium内部某一具体C++对象。

修正仅在阅读文档、水平墨迹完整容纳且垂直差异最多1/64 CSS像素时，保留原生输出。
1/64对应布局单位，用于大页面偏移处DOMRect高度的舍入；宽度条件不增加容差。
确实宽／高溢出仍走原有完整适配，纸张重排上下文也保留原固定几何。
没有移除编号、交叉引用、字体、公式或正文，没有缓存跨笔记原文。
