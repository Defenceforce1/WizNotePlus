# WebEngine 内存详细定位

2026-10-26，对当前自用 build242 进行独立合成诊断。关闭后的主进程驻留和打开时
的渲染进程占用是两个问题：前者主要线索仍是默认堆空闲及碎片，后者在大文档
编辑器和数学路径中明显放大。本轮没有产品修复，不改变242的App、安装包或资料。

## 对照范围

macOS 27.0.1 arm64，匹配Qt 6.11.3和242资源。每组同一个临时持久profile，
6000段合成正文，900×600隐藏Cocoa窗口、实际Metal后端；逐阶段异步加载、阅读、
编辑和关闭，不抓图、不强制GC、不清缓存、不改变图形后端。每组24次，每8次
保持profile存活空闲10秒。四组共96次关闭，560项工作负载和生命周期断言通过。
这是内存负载核对，不是重复完整公式或PDF功能矩阵。

完整正文返回组逐次比较原文；摘要组只回传UTF16长度和32位FNV摘要，减少诊断
向主进程回传约1.1MB文本的干扰。后者是较弱的负载一致性检查，不替代逐字原文
验收。静态对照不加载编辑器、数学脚本或Channel；无公式编辑器组仍走正常初始化。

## 关闭后的主进程

| 对照 | 第8次后空闲 MiB | 第16次后空闲 MiB | 第24次后空闲 MiB | 最后一次活动malloc MiB |
| --- | ---: | ---: | ---: | ---: |
| 编辑器及128式 完整正文回传 | 56.84 | 54.78 | 57.99 | 20.25 |
| 编辑器及128式 摘要回传 | 81.75 | 58.92 | 59.30 | 20.74 |
| 无脚本静态正文 摘要回传 | 64.91 | 72.28 | 72.74 | 19.64 |
| 无公式编辑器 摘要回传 | 66.19 | 52.72 | 46.30 | 20.76 |

96次关闭后，页面、view、Quick窗口及profile持有的QObject子项均归零；自有渲染
进程也全部退出。关闭profile再空闲10秒，主进程分别为58.30、59.67、73.11、
46.72MiB，没有因销毁profile出现显著下降。profile销毁只为诊断收尾，不是产品策略。

两组带公式对照在profile确实保持存活时，默认malloc区驻留63.9／60.4MiB，实际
分配20.1／20.6MiB，dirty及swap口径的空闲／碎片35.9／33.4MiB。原生采样中
可复用页也出现明显变化。区域摘要通过确认回执后才允许销毁profile，修正了
旧诊断在析构附近观察的时点歧义；不同计账仍不应逐字节相减。

这些数据不支持“profile一直保留全部已关闭正文”或“公式独有的关页泄漏”。
取消完整正文回传也没有消除高水位。96次不是长期无泄漏证明，样本活动malloc
仍有约1至2MiB的批间变化，缓存、观察记录和未识别分配的贡献尚未逐项拆出。

## 打开页面时的渲染进程

通过页面公开renderProcessPid取得自有helper PID，再核对完整规范路径及父进程。
不是使用截断进程名猜测，也不把共享库RSS当作独占内存。

| 对照 | 阅读就绪时渲染进程footprint范围 MiB |
| --- | ---: |
| 无脚本静态正文 | 60.44至65.81 |
| 无公式编辑器 | 580.22至760.28 |
| 编辑器及128式 完整正文回传 | 1003.88至1193.08 |
| 编辑器及128式 摘要回传 | 1002.67至1182.38 |

这份6000段大文档中，主要打开成本位于渲染进程，不能只看主进程。静态页与编辑器
的DOM和初始化不同，四组不是单一函数的精确归因；也不能把这些数值推广到普通小笔记。

另用第二个同一诊断程序做两组单次补充观察，各8项通过，单列16项，不混入上述
96次同二进制对照。保持页面打开，取得标准DOM指标及粗粒度performance.memory，
再只读获取该自有渲染进程VM摘要，未读内存正文、附加调试器或绕过权限。

| 补充观察 | 无公式编辑器 | 编辑器及128式 |
| --- | ---: | ---: |
| DOM元素数 | 12029 | 18381 |
| 页面高度 px | 422441 | 425994 |
| JavaScript报告在用堆 MB 十进制粗粒度 | 24.5 | 286 |
| VM摘要时footprint MiB | 540.0 | 767.2 |
| App Specific Tag 16脏页 MiB | 430.5 | 654.5 |

VM摘要晚于就绪采样，其footprint已经回落；原生记录的峰值分别为919.5MiB和1.2GiB。
JavaScript堆是浏览器粗粒度估计，不能与原生区域做精确差分，也不能把标签16直接
等同于某个具体分配器或MathJax对象。虚拟地址空间中的1.2TiB不代表占用1.2TiB内存。

目前已将打开时的大头缩小到渲染进程的应用专用内存区域，并看到数学路径中的JS堆
增量；尚未定位具体产品分配调用点。已核对交付包与自有MathJax兼容层哈希一致，
语音及语义增强配置关闭，不将本现象归咎于语义增强。

## 源码审阅及后续方向

普通笔记共享profile由qApp持有，跨笔记存活是既有设计。标签页关闭接线经过
destroyTab和deleteLater，独立窗口启用WA_DeleteOnClose；本轮只审阅源码，没有
用隔离QWebEngineView冒充真实主窗口全部关闭路径验收。

下一次若进入修复阶段，优先针对大文档渲染过程逐段观察自有初始化、Markdown及
MathJax兼容层的临时对象、DOM快照与内存峰值，再选择可确认的最小改动。关闭后
的默认堆驻留继续保留为已知限制，不通过定时清缓存、重建共享profile或强制回收
掩盖。本轮不升级组件、不修改受限编辑器、不制作安装包、不恢复自动任务。

## 诊断证据修正

初始探索组将proc_listchildpids的PID数量误当字节数，漏计helper；24次原始记录
保留但不计最终对照。修正后用自有sleep子进程验证采样器及非ASCII摘要，再运行
四组。首个有效组的后置路径守卫把Helpers链接和Versions/A规范路径误判为不同，
最终汇总逐个核对规范路径、PID、实际采样和程序哈希，未为路径拼写重跑负载。

原始证据仅本机保留在outputs/exploration-20261026/phase245；GitHub仅同步测试
源码与本去敏记录，不上传PID／机器路径日志、二进制或任何账户和笔记资料。
本轮新建的合成构建及隔离资料336份文件、28980489逻辑字节，在无占用核对后
移入废纸篓并保留恢复映射，源码及必要证据保留。未清空废纸篓，也不声称物理
空间已经释放；以后继续诊断需重建，不恢复旧试用入口。
