# 第330轮：初始化期间切换笔记导致空白页

2026-10-29。用户报告build329普通富文本与Markdown均空白，等待30秒仍不显示，保存提示
“页面编辑器尚未就绪”。用户要求暂停制作安装包，并清理额外测试资料目录。

## 已复现的根因与修正

上轮包内137项控制没有覆盖完整主程序的页面加载／初始化与原生切换衔接，不能据此
否定用户反馈。本轮使用真实MainWindow、合成数据库、原加载器、编辑器桥接与当前源码
复现：首篇页面加载完成但尚未初始化时，再在同一视图打开其它笔记，原viewNote先递增
当前文档代次并撤销访问，随后保存返回editor-unavailable而拒绝新笔记。旧初始化已被
取消，旧视图却被保留，形成未就绪／空白状态。基线出现保存警告、initialized=false、
setup缺失及正文不可见；不是公式排版失败，也没有改写真实笔记来复现。

修正只把“请求切换”与“当前已提交文档身份”拆开：用独立递增请求序号淘汰过时保存
回调，旧快照接受后才推进当前文档代次并撤销旧作用域。保存拒绝时，旧初始化、授权及
原DOM继续保留。没有把未就绪当作保存成功，不强制丢弃或清空正文，不添加后台轮询。
非常早的操作仍可能收到原保护提示，但关闭提示后原页能继续就绪；本轮没有取消该提示。

## 验包遗漏：实际Qt加载路径

新CMake主程序仍带绝对开发SDK的LC_RPATH。旧check-bundle只检查包内是否存在依赖，
不能证明实际加载的是包内版本；此前依赖检查的保证范围不足。本轮给新建的330副本
设置优先使用@executable_path/../Frameworks，保留机器无关的合法路径；扩充只读验包工具，
拒绝开发目录搜索路径／越界路径并要求主程序包含包内Frameworks搜索。新复制精简工具
也接入同一处理，避免后续新构件再次遗漏。未修改任何冻结旧App／DMG。

旧329作为反例被新工具拒绝；330副本48项原生依赖／架构及严格ad hoc签名通过。
最终合成主程序不设置DYLD覆盖，实际映像来自330包内Core（SHA256
a058c0a7f5434798abda672e7de8b6cb85b1a857a9f0e61c29e4473bdcb2a47f），
740项资源与既有当前源码相符。没有把同版SDK与包内映像的哈希差异直接称为老组件
或用户故障的唯一原因；原生切换故障已另行实际复现。
