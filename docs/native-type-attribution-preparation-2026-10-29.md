# 第319轮：固定容器类型诊断已准备，尚未应用或进行原生测量

318已确认频繁小请求，但不能从256–1023字节区间或页池空间反推具体类型。
本轮只读核实同版公开源码的类型元数据链，准备三文件方案及独立校验，没有
扩大正在使用的诊断引擎补丁，没有运行第三个318组或新原生组。产品仍292，
高内存未修复。下一实施需要新增类型归因范围授权。

## 已确认的来源与方案

公开分配派发器传入GCInfoTrait<实际GCInfoFolding结果>::Index()，两条自定义
空间入口已有该参数，故可直接分类成功请求，不读取对象头、地址或对象关系。
类型表按每个注册原子记录索引，不按对象或调用点记录；不同类型的重复／折叠
不能靠数字猜测。方案完全复用公开分配路径的折叠类型，并检测登记冲突。

只准备下列六个已核实用途的HeapVectorBacking元素类型：

| 固定类别 | 元素类型 | 来源与解释限制 |
| --- | --- | --- |
| node_backing | Member<Node> | 节点快照、变更列表等共享此类型，不能区分调用者 |
| element_backing | Member<Element> | 选择器结果等；不等于只有querySelectorAll |
| inline_item_backing | Member<InlineItem> | 行内排版项目列表 |
| inline_break_token_backing | Member<const InlineBreakToken> | 行内并行流断行标记列表 |
| parser_task_backing | HTMLConstructionSiteTask | 通用HTML解析任务；不覆盖所有快速解析用途 |
| selector_arena_backing | CSSSelector | 选择器arena容器 |

Member向量、解析任务及CSSSelector已有明确的可移动traits；拟加入静态断言，
要求实际SpaceTrait确为CompactableHeapVectorBackingSpace，编译不符即停止。
InlineItemResults曾作为审查目标，但其清空未使用槽位宏本身并不证明属于该
自定义空间，未凭名字相近将其纳入白名单。原生编译资格仍未验证。

在Document主线程首次构造函数体登记六个固定元数据索引；只在TLS内匹配，
不输出索引、不保留每对象记录、不调用类型名回调或遍历堆。初始化列表中的
更早请求记为before_registry；未知类型记为other_type，共享／冲突索引记为
ambiguous_index，不能拿首个匹配类型冒充唯一归属。登记错误或未完成拒绝验收。

该登记可能比正常分配更早创建类型元数据、改变登记顺序，六次比较也有观察
成本。方案不改变分配／GC／DOM规则，但不能把未来诊断数值当产品净收益。
计数仍是同OS线程各cppgc堆的成功CustomSpaceIndex0分派累计payload，不是
存活量、池页归属、调用栈或某篇笔记。实际扩缩容不纳入本次类型统计。

独立C++模型29断言通过：注册前、未知、冲突隔离、非法／重复／变更登记、
大小边界、与318逐桶对账、饱和保护和真实线程局部隔离。过滤器28断言通过：
精确64位数字、原生自动父容器、固定字段、未知类型／索引／字段拒绝、元数据
状态、溢出及逐桶总和／最大值不一致拒绝。未重复上轮未覆盖父容器的盲点。

未来原生输出为9类别×9区间×4固定字段以及4个状态数字；每个区间的类型次数、
payload之和和最大请求必须分别与318原分配计数精确匹配。未知、冲突和登记前
均保留在对账内，不因覆盖不足而丢弃或改名归因。模型通过不是原生覆盖通过。
