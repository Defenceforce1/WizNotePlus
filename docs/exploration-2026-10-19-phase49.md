# 第四十九轮：错误提示期间关闭整个窗口

2026-10-19，14.4.21 开发目录。仍暂停打包、部署、签新副本及安装，不访问真实账号。

第四十四轮已保护渲染错误提示返回后的视图和延迟重载，但未验收提示期间销毁整个父窗口。进一步核对 [Qt 官方 6.11 分支的 QMessageBox 实现](https://github.com/qt/qtbase/blob/6.11/src/widgets/dialogs/qmessagebox.cpp)：静态帮助方法使用栈上对话框，接口说明明确限制执行期间删除父窗口；[QDialog 的 exec 实现](https://github.com/qt/qtbase/blob/6.11/src/widgets/dialogs/qdialog.cpp)则会检测动态对话框在嵌套循环期间销毁。这是官方分支约束参考，不把分支版本冒称本机 SDK 的精确源码提交。

渲染错误提示改为同样的 QMessageBox 构造器、原父窗口、问号图标、文字和“是／否”按钮，仍同步执行原模态选择；使用弱指针保管动态对话框，父窗口已关闭就不再读取它或安排重载。正常返回后立即清理，没有新增提示或重试，原“否”及“是后重载”测试保留。

新增三项实际产品类测试：不崩溃渲染器，只发出原有错误信号；在真实提示循环中销毁它的实际父窗口，验证原提示属性、父窗口／视图／提示均清理、没有遗留模态界面。原启动专项增加到 **72 项，连续五轮通过**。本轮没有故意运行旧栈上弹窗去造成非法释放，不声称旧原始版本已被 ASan 或崩溃独立复现，也不把离屏弹窗验收当作所有原生系统面板的验收。

最终完整 **20 组／826 项通过**，用时 125.73 秒，含真实 Cocoa 拼写检查。离屏图形诊断仍保留，没有把它当成全 GPU 验收；本轮未重跑完整原生窗口。页面替换期间的旧错误重载仍单独核查，不把父窗口销毁测试冒称涵盖全部页面代际。原 Markdown／数学／CSS／PDF、数据格式、同步退出策略及主图标不变。源码保持原 BOM／CRLF。
