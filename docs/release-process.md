# Apple Silicon 自用与 GitHub 候选发行流程

当前安装版 v14.4-rc8 是临时签名、未公证的候选版。2026-10-14 用户明确选择不付费，允许源码和未公证安装包放到 GitHub，优先个人多台 Mac 使用，不要求上架 App Store。开发者会员、Developer ID 和公证不是此路线的默认前置条件；自动测试仍不替代真实账号验证和再分发许可核查，也不能把候选包称为已公证版本。

下次构建先处理 next-build-requests.md 的自动隐藏关闭按钮及断网退出问题，之后推进免费签名条件下的原生剪藏扩展。系统不允许扩展加载时如实报告，尝试支持的替代方案，不以关闭系统保护绕过限制。

## 工程检查

以 GitHub 兼容分支的确切提交构建。保留上游 GPLv3、第三方声明、对应源代码、固定依赖版本和构建步骤；不要打包任何个人资料库。当前使用 Qt 6.11.3、Crypto++ 8.9.0 和固定版本子模块。Qt 动态库随包提供，不要求用户安装开发环境。

构建后跑全部兼容测试，部署后再次跑网络、启动、搜索、导入导出、CSS 和真实主窗口隔离检查，执行 build/osx/check-bundle.py 与严格签名验证。检查 Info.plist 的构建号、独立标识以及无旧系统 URL 注册。最终 ZIP 解压后重新验证，生成 SHA-256。

部署包自测使用 build/osx/test-packaged.sh（显式 QT_QPA_PLATFORM=cocoa）；不要直接沿用 CTest 在 SDK 下的 offscreen 环境，最终 App 不包含该可选测试插件。真实主窗口测试仍用精确的 --mac-window-controls-self-test 路由和临时资料，不能回落到正常账号启动。

## 免费、自用和未公证候选包（当前选择）

打包脚本省略第四个参数时使用临时签名。发布时明确标注实际是临时签名、开发签名或未签名，以及未公证；附架构、最低系统、确切源码提交、构建步骤、许可声明、SHA-256 和实际验证范围。不把严格临时签名检查等同于 Apple 身份验证或公证。主 App 与分享扩展分别验证，不能只因主 App 可启动就保证系统接受扩展。

用户可在 Xcode 自行创建免费的 Apple Development 身份，凭实际能力完成本机扩展联调。开发身份的能力、描述文件、目标机器和有效期可能限制多机部署，逐台核对，不承诺无期限通用安装，也不自动要求付费。不要索取聊天中的密码或私钥。

## 完整安装包与多机便利性（交付目标）

当前用户的便利性交付目标是完整 DMG、拖入 Applications 后使用，另可提供 ZIP。运行依赖和 Markdown/数学/CSS 资源随主程序提供，普通使用不需要开发工具。源码、许可、校验码和简短安装/升级/回退说明随发行提供或在同一 Release 中明确链接；不把开发探针冒充可用剪藏器。应在另一台没有 Qt/Xcode 开发依赖的 Mac 验证启动、编辑、PDF、退出及扩展加载；这项多机验证尚未完成。

主程序选择免费临时签名；剪藏扩展首先验证系统接受的免费加载路径，必要时使用 Personal Team 的 Apple Development 做开发联调。这不是统一要求每台使用机器准备证书，更不是已获得通用发行资格。是否需要按机器开发签名和维护描述文件，以实际扩展测试结果为准。

## 可选付费签名与公证（不执行）

需要 Apple Developer 账户中的 Developer ID Application 证书及对应私钥，以及用户自行准备的 notarytool 钥匙串配置。不要在源码、聊天、环境日志或 GitHub 中提交私钥、密码与公证凭据。

打包脚本第四个参数可填写有效 Developer ID 身份。使用 Qt 官方 macdeployqt 的 sign-for-notarization 选项，启用签名、Hardened Runtime 与时间戳；Qt WebEngine 自带的 helper entitlements 随其部署。不使用上游旧 App Store 沙盒／团队共享 entitlement 来签独立版。

```sh
bash build/osx/package-arm64.sh QT_PREFIX BUILD_DIR OUTPUT_DIR 'Developer ID Application: YOUR_NAME (TEAM_ID)'
bash build/osx/notarize-arm64.sh 'OUTPUT_DIR/WizNotePlus Apple Silicon.app' YOUR_NOTARY_KEYCHAIN_PROFILE
```

上述是配置形式示例，不是本次成功执行记录。脚本会拒绝没有有效身份的签名请求，以及临时签名或没有 Hardened Runtime 的公证输入。公证必须 Accepted，然后 staple、validate 与系统评估通过，再次测试启动、WebEngine、编辑和 PDF；最终归档后重新生成校验码。没有证书时停留在明确标记的候选版，不关闭系统保护来冒充正式签名。

Qt 官方部署依据：[macOS Deployment](https://doc.qt.io/qt-6/macos-deployment.html)。

## 原账号与回退

由用户在备份后完成登录和受控双向同步测试；代理不替用户确认同步删除或发送真实账号凭据。测试正文、附件、标签、加密笔记、修改冲突、断网恢复和退出重开。首次不要批量移动、导入或删除正式笔记。

仅替换 App 不主动改变数据目录和数据库格式。回退到旧候选程序时仍必须退出当前程序并保留资料库备份。本地回退不能撤销已经同步到云端的修改或删除。v14.3 留作工程对照，含关闭证书验证的遗留问题，不推荐回退后用主账号联网。

## 公开发布闸门

工程/安全检查、许可与对应源码核查、隐私排除和发布说明达到相应标准后，可以创建明确标注“测试/候选、未公证”的 GitHub Release，不要求先购买会员或完成公证。真实同步、已知退出卡顿和新剪藏功能的实际验证状态需写清楚；若存在可能损害用户数据的未解决问题，应先修复再发布。CI 产物不自动等于正式验收，不承诺尚未发行或未实际测试的系统兼容性。当前仍有素材/字体、部分编辑器依赖与对应源码缺口，用户接受未公证并未消除这些缺口，不据此直接上传正式安装包。

若将来另行选择已公证发行，再走上面的可选流程；上架 App Store 需要另行授权，不在当前计划内。GitHub 中不得包含账号、笔记、钥匙串、私钥或未经筛除的个人报告。
