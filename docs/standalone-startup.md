# 独立 App 的启动与数据目录

v14.3 开始，直接双击“WizNotePlus Apple Silicon.app”即可，不再依赖工作区或启动脚本。可将 App 放入用户自己的“应用程序”目录；不要覆盖旧版。基础版本仍为 2.12.0。

## 默认目录

`~/Library/Application Support/WizNotePlus-AppleSilicon/`

笔记、显式 INI 设置、正文 CSS、网页资料与缓存，以及每个进程的工作临时目录，都由独立目录管理。Bundle Identifier 和 Qt organizationName 使用 `io.github.defenceforce1.wiznoteplus.applesilicon`，可执行文件仍名为 WizNotePlus。

应用位置与数据位置分离：移动 App 不会移动笔记；删除 App 不会自动删除资料库。先正常退出 App 再复制或备份资料库。

首次打开说明本地目录与云端同步边界，默认“取消”；点“开始使用”后只记录本机确认，下次不再重复。这个确认发生在账号与网页资料初始化之前。本地隔离不是云端隔离，登录账号仍可能同步该账号的笔记。当前仍请使用测试账号。

## 沿用测试笔记和 CSS

本 App 不会自动扫描、复制或迁移旧版真实资料库。当前工作区的专用测试目录可以在客户端完全退出后，完整复制到尚不存在的默认独立目录；源目录保留，不移动、不覆盖目标、不合并不同账号。

必须完整保留原有文件夹与 INI 文件，仅复制正文或另建账号目录可能丢失设置。正文 CSS 的设置键与模板注释未变，完整测试副本可沿用，不用重新添加模板。

复制阶段用 `.standalone-copy-in-progress` 防止 App 打开半成品；只有所有文件校验完成后才移除该准备标记。复制失败时保留源目录与目标半成品，不应手工去掉标记来强行使用。

旧脚本的 `WIZNOTE_DATA_STORE` 显式覆盖仍支持用户主目录内的独立绝对路径；空值、相对路径、旧 `.wiznote`／WizNote／旧沙盒容器、整个主目录、符号链接和特殊文件被拒绝，不会回退到旧版。通常不需要设置这个变量。不要同时运行两套同账号测试副本。

同一目录由会话文件锁保护，第二份进程不能同时进入；正常关闭释放锁，注销重启在数据库与网页资料关闭并释放锁后启动同一确切新版文件。失败路径不做旧资料库清理。

## 与旧版的边界

- 新版不接管系统中的旧 `wiz://` 链接注册；笔记内部的原有链接处理不变。系统外部打开旧链接可能仍由旧版负责，这不是新版入口。
- 不写入旧 Safari 剪藏器的共享账号信息。8848 端口仍只能由一个客户端占用，旧剪藏器登录未解决。
- 没有经验证的新更新通道，所以旧版上游更新查询停用，偏好设置中的自动更新选项暂不可用。以后手动替换新版 App 时保留资料库。
- 临时签名，未公证；本地隔离不等于恶意内容沙盒，CSS 与文件链接仍应只使用可信来源。

只验证合成启动场景与当前专用测试副本；真实账户登录、长期同步、全部内容读取、系统安装后的 Finder／Dock 人工操作仍需实际使用确认。原 Markdown、CSS 模板、编号规则和“另存为 PDF”未改写；PDF 引用定位偏移继续保留。
