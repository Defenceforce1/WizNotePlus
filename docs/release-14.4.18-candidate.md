# 14.4.18 候选版 — 三秒无进展退出

日期：2026-10-17。基于 14.4.17 候选，按用户最新确认缩短退出同步等待。保留编辑方式、原始笔记／附件容器、账号及同步身份、资料目录、原图标、CSS／数学环境和原“另存为 PDF”入口。独立剪藏器不变，不自动安装或移动资料。

## 本轮产品变化

- 先确认本地笔记实际保存成功；本地保存确认及原退出清理不受三秒网络时限影响。
- 最后同步连接／启动最多等待 3 秒；启动后连续 3 秒没有真实响应／传输／同步进展，即结束本次退出等待，不重试。有真实进展的长传输没有三秒总时限。
- 超时／完成决策不可被迟到活动重新激活；不永久修改系统或 App 的联网状态。未上传内容保留本地，下次正常使用再同步。
- 沿用原退出进度／取消、本地失败提示与取消退出保护；不增加确认弹窗。

三秒是偏积极的策略。服务器忙或请求计算时间超过三秒，也可能被本次退出判为不可用，并不证明物理网络已经断开。不能因此丢弃未上传数据，也不能对用户声称整个退出过程必定三秒完成。

## 验证与范围

源码完整 15／15 组、602 条命名检查通过；保存退出夹具 57 项通过。真实本机回环测试：完全不响应的请求约 3.02 秒取消；一度传输后停止的请求在最后一次实际活动三秒后取消；每个截止用例只发出一个请求。持续传输四秒的响应仍完整完成。合成时钟还验证三秒边界、两分钟持续进展以及超时后的迟到活动不会恢复等待。

初轮新增夹具把单个字节与响应头同时送出，未触发 Qt 合并后的 `downloadProgress`，因此没有建立“已经开始进展”的前提。后续在真实网络中延迟 250 毫秒发出该字节，再停止传输，验证开始后的截止；没有伪造进展或放宽三秒断言。保留首轮失败和修订后的完整结果，不将它冒称产品故障已复现。

最终自包含 App 的 10 组、516 条命名检查及独立启动取消入口通过，真实 Cocoa 主窗口 93 项通过，各测试进程正常退出。47 个 Mach-O 组件全部 arm64、零外部开发依赖失败，严格递归 ad-hoc 签名及原图标 SHA-256 一致；App 约 312 MiB。全部自动功能测试采用临时合成资料和本机回环，不登录真实账号、不对真实笔记做压力试验；不以这些替代用户全部日常场景验收。

## PDF 探索结论

生产 PDF 导出**没有改变**：仍直接导出当前渲染页面，不把 Markdown 转成另一套排版，也不增加独立打印 CSS 或重写 PDF。

旧样本中普通标题和数学块的 PDF 链接落点都随页边距发生额外偏移，说明不只是 LaTeX 或数学块样式的问题。连续滚动页面转成 A4 会重新分页，PDF 中链接目标的坐标还须单独正确处理；文字、公式可正常显示而点击引用的落点不准，是可以同时发生的。

新实验将页边距仅放在临时 `@page` CSS，API 边距置零，仍使用同一 `printToPdf`。结果链接中随边距变化的额外偏移消失，但指定的 5／20 毫米实际都变成相同的零 API 边距：普通样本由原 3／4 页均变 3 页，跨页样本由原 5／6 页均变 4 页；后续页面文字几乎贴边。图片对照已检查，原文／公式／修改状态没有变化，仍因页边距及分页不兼容而否决。此实验只在独立探针，不进入产品。

所以内容导出本身已经工作，当前难点是打印层的链接坐标和分页／页边距一致性。尚未锁定到 Qt／Chromium 源码中的具体缺陷行，也没有用固定像素补偿或取消边距来掩盖问题。
