# 固定测试资料与启动入口

后续组件候选共用 `outputs/WizNotePlus-测试资料`，不再把资料放在每个build目录内。
日常资料目录规则不变；现用App、真实资料、重要回退安装包不参与合并或迁移。

本机固定入口为 `outputs/启动测试版.command`，当前指向build226。226包内入口也
使用同一目录；保留整个项目输出结构，不要单独复制App直接启动。后续交付只更新
固定入口的候选路径，并用 `build/osx/launch-test-candidate.sh.in` 渲染包内启动器，
替换build编号与已验证的可执行文件SHA256；不要恢复按版本创建资料的旧规则。
旧版启动器为历史构件，不再使用，否则它可能重建旧测试目录。旧App与重要镜像
未覆盖；有不兼容资料格式升级时须另行说明，不让旧版自动读取新格式资料库。

本次检查发现214、218、219、221、222共5份试用资料，保留最新222的完整目录，
通过同卷原子重命名移入固定位置，逐项元数据摘要／inode验证保持；不拼接数据库、
不读笔记正文或密码、不导出钥匙串、不自动登录。其余4份移入废纸篓；另清理45份
UUID隔离测试的空配置及1份reader-opening测试缓存。恢复映射仅存本机私有证据，
不上传账号、目录内容或二进制。未清空废纸篓，不声称已释放磁盘空间。

登录设置随目录原样保留，不强行启用“记住密码”或“自动登录”。固定目录解决换包
即变空账号库的问题；用户主动退出、服务器会话过期或原先未保存登录时仍可能要求
密码。没有通过保存明文密码绕过登录，也不保证任何情况下永不重新认证。用户登录
后仍可能正常云同步，固定本机资料目录不是离线沙盒。

只做启动入口关联检查：模板一致性、shell语法、实际签名／摘要／非GUI路径验证、
重复启动路径保持、忽略继承的资料路径覆盖、参数拒绝、文件元数据保持、不重建
版本资料目录。不启动真实账号检验登录、不重跑公式／PDF／数据库全量测试，也
不把目录原样保留当作真实云端登录成功的验收。自动任务保持暂停。
