## 旧引擎能否自然回收

script.onload／onerror在完成后仍挂在脚本节点上，先把它当作可验证的持有假设，
没有直接宣布泄漏。仅观察公开MathJax对象、MathDocument、Hub、body和首个输出的
WeakRef；身份索引为WeakMap，结果只存标量。未连接SPAN作为回收控制；不采私有堆栈。

三次读编后，参考引擎身份1→7→13→19，回调清理候选也相同。0／10秒部分旧对象仍可
解引用，30／35秒旧引擎、旧MathDocument和未连接控制都已自然回收，当前130个公式
输入／输出与原文保持。回调清理候选空闲占用没有改善，因此不合入这种无收益整理。

## 决定性反例：旧宏会污染新原文

合成可编辑DOM先设置：

```latex
\begin{equation}
\def\WizSyntheticMacro{A}\WizSyntheticMacro+B
\end{equation}
```

回到编辑后删除定义，只保留命令，再回阅读：

```latex
\begin{equation}
\WizSyntheticMacro+B
\end{equation}
```

参考每次新引擎，最终呈现未定义的命令；候选直接复用，即使保留原有texReset和
Reprocess，也继续把它显示为A+B。两边实际getMarkdownSrc均等于修改后的原文，
故不是编辑器没有接收删除操作，而是TeX宏状态残留。实际公开toMML结果去除属性后
的可见文字及完整MathML均保留；不是仅看源码data-latex属性或错误标签数量猜测。

参考4检查全部通过，候选3通过／1个语义失败，原生结果亦记录失败；未降低断言要求。
初稿使用本组件不支持的gdef，且只检查merror漏掉红色未定义命令文本，两边均失败；
改用确认支持的def、分别检查定义有效和删除后可见文字，初期错误完整保留。

因此直接复用拒绝，终态回调清理也拒绝；没有把省内存候选交付给用户。不加宏命令
黑名单、不改私有解析器表、不用旧原文缓存掩盖。以后若继续这条路线，必须有公开
API契约能建立等价的新解析状态，包括用户宏、编号和包状态；保留texReset本身不够。
