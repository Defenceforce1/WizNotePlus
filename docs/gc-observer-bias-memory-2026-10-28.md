# 高峰同场回收事件与诊断观察偏差

2026-10-28，第301轮。新独立入口捕捉到当前程序约540MiB高峰和当时的自动回收事件；
浅克隆同码在有追踪时约349MiB、无追踪时又约540MiB。低峰对诊断方式敏感，不能
用它证明稳定内存改善。产品保持292，候选仍未合入，实际高内存未修复。

## 减少正式负载中的观察停顿

先检查既有同版本地Chromium文件追踪实现。桌面文件输出会先写普通临时文件，最后
改名；把最终目标设为FIFO也不能避免原始临时记录落盘。因此未执行启动文件／FIFO
方案，未故意制造目录失败或修改上游。来源和精确行段存public-contract-review.json。

改用独立诊断入口：新建同一个空白页，在加载第一篇合成笔记前完成自有回环连接、
公开版本／类别／时钟核对和Tracing.start；正式大／小切换期间不再发送CDP查询。
仅在最终30秒空闲后复核时钟并停止追踪。固定v8／cppgc类别、8192KiB缓冲，无JS栈
采样／系统追踪／memory-dump触发器；只保留自有renderer固定GC名称、时间、时长、
堆数字及固定回收原因，原始事件／地址／对象内容不写入。

额外空白上下文是新的诊断条件，不把新入口与历史入口的差值直接称收益。本轮所有
有效组使用同一个49b331诊断二进制、同一份输入、同样13次笔记加载及六轮切换、
1.5秒间隔与10／30秒空闲，profile／view各一，不循环重建；原文检查、质量、TeX
字体及语义增强关闭保持。默认组件逐字复核196资源、15组150组件；Qt6.11.3／
MathJax4.1.3／当前helper完整路径、正常Cocoa和实际Metal保持。没有产品重编。

初次准备错误假定Node和公开Timestamp具有相同原点，在空白页阶段停止、未开始
负载或追踪，失败完整保留。修正为请求前后夹住的实测时钟偏移，并在最终验证经过
时间一致性；不把两个原点混为一谈。三个追踪组均完成漂移／不确定度核对，无数据
丢失。此失败不算有效内存组，也没有删除或改写原记录。

参考组第一小页读取后已用堆约41.5MiB，期间没有major；第二大页之后footprint由约
277跃升465MiB。其后切回小页仍约48MiB已用堆；完整记录中各小页之间均无major，
下一大页期间才再次回收。两个候选低峰组则每次切小后都有自动task finalization，
下一大页前堆回低位；末尾自然空闲中的reduce-memory finalization之后均显著回落。
这比原先仅看堆数字更直接支持“页间未及时完成回收，新分配抬高峰值”的机制，但
这些GC事件仍不是具体对象／分配点证明，也不能把全部物理驻留归到JavaScript。

## 同码无追踪再次反弹，观察成本不能忽略

同一浅克隆方法、资源路径、二进制和输入，关闭追踪／调试端口、仅保留原有原生
采样的组又达到约540MiB。第二小页已用堆约47.4MiB、footprint约299MiB；第三大页
footprint约460MiB，复现了300所见的“已用堆先分叉，下一大页才明显跃升”。

这表明额外空白页并没有消除反弹，也不能认为只要把诊断连接提前就没有扰动。追踪
低值与更多页间回收同现；没有进行随机化大样本因果试验，故称“观察偏差是重要限制”，
不把一组对照当所有低值都由追踪造成。299本来已有无诊断低峰354MiB；那份正向
记录也保留，但其后同码510／539MiB及本轮无追踪540使稳定最坏峰值仍不合格。

## 新反差支持的两组较窄日志尝试

在既定4组之后，唯一有界增补是两组公开V8 trace-gc-nvp自动完成日志，无CDP／
Tracing／监听连接。先核对当前本地旗标定义、StopObservablePause／PrintNVP和Qt
命令行传递来源：只打印既有回收后的数字，未设置GC间隔、堆阈值、压力、强制GC
或缓存策略。该诊断开关只传给独立测试进程，未进入主程序或用户启动入口。

写盘前丢弃原始行与isolate地址，仅保存目标PID、引擎经过时间、固定kind／reason、
选定堆容量／已用／分配限制等数字；其它阈值／pool前缀行也丢弃。没有对象／私有
栈或正文。首版minor kind拼写表改为源码的mms，首组实际仅收到s／mc，不改变原始
结果；初版采集器也保留。两组各72控制、15屏障、28原生样本通过。

没有回收，不能把日志列表冒称完整系统事件。完整性限制单独记录，无故意flush／GC
或保护机制改动；不继续反复运行同样两组来选好结果。

## 收敛结论

高峰与页间major缺席在当前292参考中已有同场证据；候选同码高峰仍缺低扰动、完整
事件，观察方法会影响分布，不能宣布上一轮354→510的全部具体原因已确定。
当前最有力解释仍是自动回收时序与Blink页池保留，并不支持已找到持续泄漏或具体
自有对象持有点。单纯减少局部DOM操作，并不能保证最坏物理峰值同步下降。

六个有效组共432原文／当前输出／退出等控制、90屏障、168原生样本，所有自有窗口
和renderer退出，无外部请求。没有产品行为变化，因此不重跑公式／双PDF大矩阵；
旧2处严格DOM失败和历史限制保留。额外准备失败、低值和高值都保留，未强制GC、
加压、清缓存／历史或降低画质。
