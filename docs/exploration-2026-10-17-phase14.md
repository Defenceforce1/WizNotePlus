# 第十四轮：插入链接窗口的生命周期

2026-10-17。本轮修复主程序源码中的链接弹窗边界，仍保持原编辑器、快捷键、链接输入界面及地址默认规则；不改笔记格式、CSS／数学、同步策略、账号、资料目录或图标。**仅形成开发源码候选，不生成或安装新 App**。现用 14.4.17、已交付 14.4.18 和冻结 14.4.16 均保留。

## 发现与修复

源码审查发现，插入链接原先直接捕获编辑器指针处理异步 JS 结果，未验证所属笔记是否仍存在／仍为当前文档；弹窗归属整个主窗口，且在 WebEngine 回调里运行嵌套 `exec()`。这是可导致生命周期错误的代码路径，**不是把用户此前某次崩溃归因于此**。

另一个问题可直接复现：原代码把地址放进单引号脚本，地址本身有单引号时无法正确传递给编辑器。测试走过原输入框相同的 `QUrl::toEncoded()` 和旧规范化过程，旧构造仍失败；安全传参后实际 WebEngine 收到完整规范化地址。

本轮实现：

- 新的 `WizDocumentLinkRequest` 仅保留弱请求状态、QPointer 及文档失效票据。替代请求、取消、导航、对象／页面销毁均阻止旧结果；未收到有效字符串前不允许确认，确认后只消费一次。
- 弹窗改由所属编辑器拥有。仍是同一个输入框／按钮和 application-modal 窗口，改为异步显示，不在 WebEngine 回调内部套事件循环。再次点击已打开的链接命令只激活当前弹窗。
- 编辑／阅读切换、载入／清空／重新载入笔记、正常关闭请求和析构前取消链接窗口。**只取消临时链接请求，不取消本地保存回调，不绕过保存失败保护。**
- 使用 JSON 字符串传递 URL。空值／`http://` 仍删除选中链接，无 scheme 仍补 `http://`，保留原有规范化和 scheme 行为；这不是新增地址白名单或改变链接语义。

## 验证

实际 Qt WebEngine 回调的共享生产 helper 新增 **16 项**检查，异步文档组从 45 增至 **61 项**，包括：

- 有效空字符串、默认 HTTP、空地址删除、带引号／Unicode／反斜线的 URL，以及旧构造失败见证。
- 查询尚未完成时确认、重复确认、取消和新查询覆盖旧查询。
- 导航前后、弹窗已显示后文档失效、所属对象／页面／请求销毁、错误页面及 undefined 结果。

完整源码回归 **15／15 组、618 条命名检查**通过；开发构建成功，仍有既有 Qt 弃用警告，不能称无警告构建。

原生主窗口测试显式设置 `WIZNOTE_TEST_LINK_LIFETIME=1`，在原隔离入口 `--mac-window-controls-self-test` 增加 **9 项**链接检查：实际弹窗所有权／模态性、重复动作、地址传递／重复确认、取消、待完成请求时切换阅读模式、恢复编辑器、第二个真实文档加载、正常关闭并销毁待查链接的文档，以及还原原引擎链接方法。全部通过。只使用临时合成数据库和笔记，禁用真实同步和远程页面请求。

其中地址提交检查用记录式链接端点观察真实原生 UI 调用，避免改写主测试笔记；它不冒充所有富文本光标位置／链接选择行为都已人工验收。初次关闭夹具失败是因为直接构造文档控件没有接入主窗口的 loader，补上与主窗口相同的真实加载／排队投递连接后通过；失败日志保留。

## 没有通过的整体界面回归

**新增 9 项通过不等于整套主窗口通过。** 本轮没有降低原来的原生焦点或标题栏几何判定：

- 一次测试停在中文筛选框原生焦点前提；通过电脑界面工具激活正在运行的隔离测试后，保留原有条件并通过该项。没有启动用户账号或旧 Intel App。
- 链接扩展运行完成 78 项后，在标题栏按钮对齐检查失败，后续依赖项停止。
- 不启用新增链接测试的普通对照完成 85 项后，也在红色关闭／重新打开后的标题栏对齐检查失败。诊断记录交通灯中心约 y=16、搜索框中心 y=21。保留这个失败，不以旧阶段一次通过代替当前验收，也不据此改动窗口尺寸或点击判断来让测试变绿。

因此当前源码**不作为新正式安装包交付**。该几何问题与链接代码的关系尚未完全排除，普通对照也出现不等于已经定位根因；下一步需与未修改候选作同条件原生窗口对照，核对显示／窗口状态及重新显示后的按钮布局。
