# 第五十六轮：先验证正文的未接收原型

2026-10-19。主程序源码保持第五十四轮；本轮只扩展独立导出诊断，不打包、不安装。

测试工程新增单独的 `markdown-export-candidate`，仅编译测试目录的原型。取得真实字符串正文（包括合法空字符串）后，才调用原数据库导出接口及原 UTF-8 写入工具；使用现有文档代际、弱窗口／页面及笔记身份检查。原型不链接主程序，不把只适用于临时 UI 的查询回调直接套在保存完成确认上。

## 实际验证

- 原型 **66 项，在 ASan／UBSan 下连续五轮通过**。Qt 自身未插桩，泄漏检查关闭；不是全 App 内存安全验收。
- 无效 `undefined`／`null`／数字／异常结果不写目标、不调用模型数据库；合法 Unicode、空 Markdown、旧资源路径替换及无 BOM 字节保留。
- 合成适配器在实际浏览器回调前销毁、作废文档代际、改变笔记身份或脱离页面，均保留临时哨兵文件。它们不是实际主窗口导航／析构端到端验收。
- 同一扩展夹具编译的原方法仍有 **58 项中的 4 项安全失败**；原型开启完整失败保护要求后，仍有 **67 项中的 1 项失败**：模型数据库在写 HTML 后失败会破坏已有目标。两者正常退出 1，失败没有被隐藏。

因此只证明“无效浏览器结果先挡住”的原型可行，**没有完成原子式正文＋资源导出，也尚未接入产品**。下一步继续检查实际数据库导出的资源处理及失败恢复；保留现有图片资源目录／链接约定，不为消除一个失败而改变笔记或资源格式。
