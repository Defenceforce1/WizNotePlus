# 第十阶段：三秒退出策略及 PDF 边距对照

2026-10-17。继续用户授权的兼容优先探索，不改编辑习惯、笔记容器／目录、云端身份或原图标。14.4.16 冻结回退及 14.4.17 候选保留；只读观察 Applications 现为 14.4.17，本阶段没有安装／替换主 App，也不操作独立剪藏器。

## 退出同步

用户最新要求：连接／启动和连续无响应／无进展都以 3 秒为截止，不自动重试。源码 `WizQuitSyncPolicy` 同时实现两个三秒阈值，且超时／完成为终态，迟到进展不能让同一等待恢复。本地保存确认仍先行、退出提交前再核对，不把本地保存和原清理计时改成三秒。只对本次退出按网络不可用处理，不永久改变联网状态，未上传内容留在本地。

纯时钟用例核对 2999／3000 毫秒边界，进展刷新后精确三秒边界，两分钟持续进展无总时限，以及迟到活动／完成不会复活已超时决策。原网络观察作用域、同属同步的资源下载进度、零字节／重复计数和无关线程隔离测试保留。

真实回环夹具不访问服务器／凭据：完全不回应的请求约 3023 毫秒停止；响应头后在 250 毫秒发出一个字节再停滞，约 3299 毫秒结束（实际进展后约三秒），每个截止请求只发出一次；持续每半秒发字节、总长四秒的响应仍完整保存。首次把字节随响应头立即发送，没有触发 Qt 合并后的实际进度通知，未满足“已有进展”的前提，导致两项断言失败；更正夹具时没有伪造网络事件、缩短响应或放宽阈值。

更新后保存退出 **57 项通过**；完整源码 **15／15 组、602 条命名检查通过**，另有生产启动取消进程检查。首轮失败和后续通过分别保留本机；原日志不上传。

三秒是用户选择的偏积极策略，不是网络连通性证明。慢服务器可能也被这次退出提前放弃；整个退出还包含本地保存和清理，不能宣称全程必定三秒。

## PDF：直接导出不等于链接坐标必定正确

生产代码直接对当前 `QWebEnginePage` 调用 `printToPdf`，没有再做 Markdown 转换／另一套公式排版。连续屏幕转成有页宽、页边距及分页的纸面，本来就会重新折行和分页；PDF 绘出的文本／公式与链接的命名目标坐标又是不同数据。因此正文正常而引用落点偏移可以同时发生，不应将它统称为 Markdown 无法导出。

既有实际 Qt 对照中，5／20 毫米边距下数学标题墨迹与命名目标上沿差值分别为 29.596／72.346 pt，普通标题为 16.644／59.394 pt；两者都增加 42.75 pt。数学块的内边距和字体墨迹本来就产生一部分正常差值，不能把这些全部算成打印错误；但普通标题也出现随纸面边距变化的额外差值，证据指向打印路径的边距／链接目标处理，不是只由 LaTeX 或数学块 CSS 造成。尚未定位到 Qt／Chromium 的具体缺陷源码行。

## 新实验：CSS @page，不改 PDF／锚点

独立探针仍用同一实际 Qt 6.11.3、原阅读器、同一合成 Markdown／数学样式，仅临时加 `@page` 的 5／20 毫米边距，并把 API 边距置零。没有移动 DOM 目标、改写 PDF、引入另一套导出或应用到产品。

普通及刻意跨页两组，共六份 PDF 生成成功，原文、HTML 恢复结果、修改状态、两块数学环境和一个公式保持一致，无远程请求。链接目标均在正确页内，标题差值在两种边距都为 15.346 pt，普通标题为 2.394 pt，符合块内边距／字体本身的残余量。

但 5／20 毫米的实际位置完全相同：普通样本都 3 页（原为 3／4），跨页样本都 4 页（原为 5／6）；后续页面首行距纸面顶部约 1.096 pt。Poppler 图像对照也确认边距缩掉、每页容纳内容改变。**这不是兼容修复**：该组合没有按希望应用 CSS 页边距，不能因为链接误差数字小就采用。生产 PDF 保持原路线，问题继续开放。

首次独立探针将 SDK 父进程框架与包内 WebEngine 子进程混用，出现 ICU 描述符错误及初始化超时，未产出 PDF；修改独立探针的 RPATH，使父子均使用候选包框架后成功。此为探针环境修正，不是产品资源缺失或用户笔记故障。没有关闭沙盒／安全保护或操作真实账号。
