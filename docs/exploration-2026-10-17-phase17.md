# 第十七轮：SVG 引用候选与打印坐标证据

2026-10-17。继续用户授权的兼容优先探索。只修改独立测试、只读审计和记录，**不改生产导出／组件／编辑器，不构建或安装新 App，不改用户 PDF**。只运行 Qt 6.11.3 的合成阅读器，不接触真实账号。

## 公式目的地：可行候选，不是已发布修复

使用原编辑器、MathJax 2.7.6 和科学 CSS，对 SVG 链接分开改变属性命名空间、片段编码和目标容器。最终普通、分页边缘、普通 `eq1` 编号三组各八份 PDF；另外两组宽度实验各三份，共 **30 份最终诊断输出**，均完成原文／HTML／修改状态恢复、公式对象、无远程请求检查。

- 原始 XLink 引用能生成 PDF 链接，但没有对应目的地。
- 只改变 XLink 地址的百分号编码，或把 SVG 目标 ID 暂移到既有 HTML 容器，都没有解决缺失。
- 在保留 XLink 的同时，给 SVG `a` 加上**无命名空间的 `href`**，保留编码和原始片段两种均成功生成确切可解析的目的地。三组共六个此类变体的目标都存在，并在预期页；这只证明引用可解析，不表示纵向坐标已经准确。
- 无命名空间 `href` 与 XLink `href` 不是按名字猜测的同一属性。实测原属性的 qualified name 是 `href`，namespace URI 却属于 XLink；必须按 Attr 的 namespace／name 操作与恢复。SVG2 规范允许同时保留旧 XLink，并优先现代属性：[W3C](https://www.w3.org/TR/SVG2/linking.html#XLinkRefAttrs)。
- 三组原输出和“补 SVG2 href、保留编码”的输出逐页渲染：**10 页 PNG 逐字节相同**。也检查了定义／公式及分页边缘的整页画面，没改变数学外观、版式或页数。

早期测试错误地依据属性名猜 namespace，先漏掉链接而主动跳过变体；随后虽得到目的地，却未完整恢复 HTML。均保留为失败证据，不当作验收。改为读取 Attr 的实际 namespace／name 后，恢复校验通过；此时也证实单纯编码／容器改动仍无效，真正有效因素是补现代属性。

尚未接入主程序。正式实现仍要处理导出期间异步保存、切换／销毁页面、重复导出及失败恢复，不能把测试函数直接拷进产品或永久改写存储的 HTML。也没有宣布公式引用已精确定位。

## 定理／定义：把文字差值与实际框位置分开

背景框顶边比标题字体墨迹更适合核对整个数学环境的锚点。只读审计从当前科学 CSS 样本的填色路径提取框顶边，记录 PDF 内容流的缩放／平移，并作统一 A4、页内目标的首面原点假设比较：

`估计绘制顶边 = 原 PDF 目的地距顶位置 × 观察到的打印缩放比 + 首面上边距平移`

普通／分页边缘、5／20 mm、两种额外视口宽度下，共 **16 组**原容器目标的估值与实际框上沿误差不超过 **0.00015 pt**。这强烈支持样本中的目的地没有按正文相同方式纳入打印缩放／平移，而不是只由标题内边距、字体或 LaTeX 造成。

默认宽度 850 时观察到缩放比约 0.944295／0.800842，上平移约 14.25／57 pt。宽度改为 756／643 可使部分输出达到名义 0.75 pt／CSS px、不再自动缩小，但原目的地仍有边距偏差；页面还从三页变成四页。**不采用调整主窗口／视口作为修复**。

首次只读估值误用后续页的全篇平移，重复计入分页而失败；纠正为统一 A4 夹具的首面原点假设后得到上述匹配。没有覆盖失败 JSON，也没有把估值写回 PDF。真实标题变体的 ID 不在背景框顶边，明确不计入这 16 组。

这不是通用 PDF 坐标修复，也没有定位到具体 Qt／Chromium 缺陷源码行。混合纸型、旋转、裁剪、任意 CSS、分裂数学框、缺少目标等情况仍不能套用这个公式。生产路径保持原 `printToPdf`，不加 PDF 后处理、强制补偿或新打印样式。
