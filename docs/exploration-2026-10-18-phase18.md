# 第十八轮：PDF 引用源码候选与保存隔离

2026-10-18。延续兼容优先探索，首次把上一轮的 SVG2 公式链接候选接入主程序**开发源码**。完整开发构建成功，但不生成安装包、不安装、不改已经交付的候选、用户笔记或原始 PDF。原编辑器、Markdown、MathJax、CSS、PDF 入口和原生 `printToPdf` 路线保持；没有 PDF 后处理、打印 CSS、视口调整、组件升级或图形默认值变更。

## 先发现并处理真实保存风险

第一版仅在隔离 world 的可信 `beforeprint` 加现代链接、`afterprint` 还原。正常输出与 HTML 还原检查虽通过，随后追加的“打印同时保存”检查却失败：Chromium 在临时属性尚未还原时仍会执行另一条 JavaScript，保存快照读到了这些属性。不能以最终 DOM 恢复或样式不变来声称它安全。

因此没有把第一版打包，改为页面级 `WizPdfPageOperations` FIFO：

- 富文本和阅读模式的两个原有保存快照入口均通过同一屏障，包括绕过 `trySaveDocument` 的直接保存调用。没有改写其保存脚本、FIFO 落库流程、修改序号或本地保存确认。
- 原生打印只有在排队到本操作时，才在 ApplicationWorld 显式准备 helper。普通页面打印／不可信事件不触发补丁；编辑状态的富文本不增加 SVG 属性。
- 物理打印完成并确认临时属性恢复后，才放行保存。取消导出只取消输出目的地，不提前放行仍在打印的页面。
- 操作与输出分别按所属对象、页面、笔记代次和一次性回调隔离。过期请求、切换、关闭、重复完成不会写入旧路径。原子保存仍只提交完整 PDF，取消或失败不破坏原文件。
- 故意注入恢复异常时，拒绝输出，并明确让该文档后续保存失败，不能把无法确认干净的内容写入笔记。正常新文档加载才解除这一保护；不自动重新载入或丢弃修改。既有保存失败处理继续生效。
- 队列销毁会以失败释放活跃及待执行保存回调。失败回调中再次排队也不能让两项同时运行。页面销毁不依赖 Qt 必须送达打印回调。

保留原先可暴露临时 HTML 的**负对照**，再以实际生产屏障和保存脚本验证恢复。没有删除或放宽先前失败的安全要求。

## 导航边界另有失败证据

加强断言后发现：取消中的 `setHtml` 导航后，新文档虽然加载完成，注册的 DocumentReady helper 在该合成时序里可能不存在。旧测试把空状态当作“不活跃”，不足以证明新文档能再次导出。

只把注入时点改为 DocumentCreation 也未通过，保留失败日志。最终在原生入口按当前文档幂等确保 helper，并实际再次打印：新的 helper 完成一次准备／恢复、只增补一个符合条件的链接。不是宣称已经定位 Qt 注入问题的底层根因；也不把恢复失败保护误应用到已经替换的另一文档。

## 最终验证

- 主程序开发构建完成。完整 **16／16 组、665 条命名检查**通过，其中新增 **47 条 PDF 生命周期检查**。覆盖原有保存退出、中文搜索／界面模型、拼写、入库重开、原编辑器及原生桥接等现有回归。
- 同版本 Qt 6.11.3、原阅读器、MathJax 2.7.6 和科学 CSS，普通、分页边缘、普通 `eq1` 三组各输出三份 PDF。**九份**输出所有具名链接均有精确匹配的目的地；原文、序列化 HTML、修改状态、公式对象及零远程请求不变量通过；每组均为三次准备、三次恢复，无待还原属性或错误。
- 三组 5 mm 输出共 **十页**，与未增补 SVG2 的基准 PNG 逐字节一致；另目视检查数学环境、公式和分页边缘的页面。说明本夹具的视觉排版未改变，不能代替任意用户 CSS 的覆盖。
- 人为恢复异常、保存队列销毁和重入、实际打印发出后取消，以及等待中的保存均有独立检查。最后一个取消用例确认物理打印确实发生，但原文件不被替换，排队快照仍为原始 HTML。
- 14.4.16 完整回退包的清单、版本、归档和严格递归签名复核通过；现用 14.4.17 可执行文件与交付 14.4.18 的可执行文件／DMG／源码归档校验保持。没有更新 Applications。

完整回归并非零告警：非屏幕测试仍出现原有 GPU context-lost 日志，已有弃用编译警告也保留。另一次 Cocoa 主窗口检查在应用未处于前台时，IME 标签筛选工具窗的键窗口断言失败；没有把它算入已通过的 665 项，也没有用重试抹掉失败。此前间歇性标题栏对齐问题仍不能宣称根治。

## 未完成和交付边界

这次解决的是公式链接缺少 PDF 目标的**源码候选**及其保存安全边界，不是定理／定义纵向偏移的最终修复。目的地存在、页码正确、页面视觉不变，都不等于 PDF 阅读器中落点准确；公式落点精度也未宣布修复。

下一步仍应围绕实际打印变换与目标坐标，扩大分页、自定义 CSS 及布局控制对照，保留原输出路线。不根据统一 A4 样本的矩阵估值直接补偿任意 PDF。原生窗口完整验收、渲染器失去响应等所有极端时序、Metal footprint 根因和发行签名／自包含整包验收也未完成，因此本轮不称最终正式版。

源码和脱敏说明通过 GitHub 插件备份到独立开发分支，稳定分支不变。具体提交、选定源码 blob、私有日志和生成样本摘要写本机阶段收据；用户文件、原始日志、截图、PDF 和开发 SDK 不上传。
